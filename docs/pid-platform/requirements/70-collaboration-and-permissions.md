# 协同与权限需求

本文档定义 P&ID 平台的协同与权限需求，共 16 条，按 6 个需求小节组织，另有「错误码表」「实现现状」「未决事项」3 个不含需求条目的小节；需求编号规则见 `docs/pid-platform/requirements/00-overview.md`。平台级的三级授权链条目是 `REQ-PLAT-010`，本文档在图纸粒度上展开；图纸权限的生命周期入口是 `REQ-DRW-007`（定义于 `docs/pid-platform/requirements/40-drawing-and-drafting.md`），本文档补齐它留下的权限粒度。权限的五个字段名 `角色`、`PBS 节点`、`图纸状态`、`允许`、`拒绝` 以本文档为权威定义处。

本文档的读法有 3 条。① 验收标准里的拒绝与失败一律引用「错误码表」登记的码名，不写数字状态码；码名、含义与提交方的处置以该表为唯一出处。② 正文写的是要求；每条要求在当前代码里做到哪一步，登记在「实现现状」一节，正文不因尚未实现而降低。③ 还没有决定的规则不写成要求，集中列在「未决事项」一节，只列问题与现状，不写结论。

## 三级授权链

授权判定沿三级收敛，判定顺序恰为 3 级：第一级 `角色权限`，即功能权限，按角色 × 操作查权限矩阵；第二级 `PBS 节点 ACL`，沿 PBS 树自根向下取最近的一条显式 ACL，节点未配置时继承父节点，根节点也无配置时该级视为拒绝；第三级 `图纸状态`。

判定式为 `判定 = 角色权限 × PBS 节点 ACL × 图纸状态`：三级同时为允许才放行，任一级拒绝即整体拒绝，响应返回首个拒绝级别与对应错误码。

与 `REQ-DRW-007` 的衔接：`REQ-DRW-007` 定义图纸权限的生命周期入口与最低权限集（`查看`、`编辑`、`导出`、`删除` 4 项）以及「未配置时 `继承自` PBS 节点」的行为；本节定义该权限集的判定链与角色 × 操作矩阵，两处不重复定义。

判定示例：

| 角色权限 | PBS 节点 ACL | 图纸状态 | 判定 | 拒绝级别 |
| --- | --- | --- | --- | --- |
| 允许 | 允许 | 单人编辑 | 允许 | — |
| 允许 | 允许 | 只读 | 拒绝 | 图纸状态 |
| 允许 | 拒绝 | 协同编辑 | 拒绝 | PBS 节点 ACL |
| 拒绝 | 允许 | 单人编辑 | 拒绝 | 角色权限 |
| 允许 | 允许 | 协同编辑 | 允许 | — |

## 图纸状态

图纸状态枚举恰为 3 个值：`单人编辑`、`协同编辑`、`只读`。这里的 `图纸状态` 专指图纸的编辑会话状态，是权限判定的第三级；它与 `REQ-DRW-003` 定义的 `生命周期状态`（设计中、已校核、已批准、已发布）是两个不同字段，不得混用同一取值域。状态决定一张图纸允许的编辑会话数与可写性：

| 图纸状态 | 含义 | 可写 | 允许的编辑会话数 |
| --- | --- | --- | --- |
| 单人编辑 | 同一时刻仅 1 个编辑会话持有写权 | 是 | 1 |
| 协同编辑 | 多个编辑会话共享同一基线修订号并发写入 | 是 | 多 |
| 只读 | 禁止一切写入，仅可查看与导出 | 否 | 0 |

`允许的编辑会话数` 数的是持有写权的编辑会话；以只读建立的编辑会话不计入，三种状态下都可以有。

状态迁移规则有 5 条：

1. 切换图纸状态是一项按 `授权配置` 判权的操作，只过前两级判定（`角色权限`、`PBS 节点 ACL`），不受图纸当前状态的限制。
2. 迁移路径：`单人编辑` 与 `协同编辑` 双向切换；任一可编辑状态可切为 `只读`；`只读` 可切回可编辑状态。可编辑状态转为 `只读` 的来源有 2 种：具有 `授权配置` 权限的用户切换；发布（见 `REQ-DELV-008`）。
3. 图纸状态为 `只读` 时没有任何编辑会话可写，不保留编辑权持有者；「一个人写、其余的人只看」由 `单人编辑` 承担。
4. `单人编辑` 图纸上持有写权的那一个编辑会话称为编辑权持有者：先建立的编辑会话持有编辑权，其后建立的编辑会话以只读建立；持有者的编辑会话结束或失效后，编辑权转给该图上仍然活跃、最早建立的编辑会话。
5. 「锁定」一张图纸指把它的图纸状态切为 `单人编辑`，「解除锁定」指切回 `协同编辑`；本文档不另设「锁定」这个操作。没有编辑权限的用户，其编辑会话以只读建立，图纸状态不因此改变。

### REQ-COLL-004 图纸状态枚举与迁移

- **优先级**：必须
- **用户故事**：作为项目管理员，我希望图纸状态枚举固定且迁移路径受控，以便并发策略按状态一致执行。
- **验收标准**：
  1. `图纸状态` 枚举恰为 `单人编辑`、`协同编辑`、`只读` 3 个值；对应允许的编辑会话数分别为 1、多、0。
  2. 切换图纸状态要求 `授权配置` 权限，只过 `角色权限` 与 `PBS 节点 ACL` 两级判定，不受图纸当前状态限制；缺少权限时返回 `PERM_DENIED_ROLE` 或 `PERM_DENIED_PBS`，原状态保持不变。
  3. 图纸状态为 `只读` 时同样可以切换：具有 `授权配置` 权限的用户把它切为 `协同编辑` 后，该图上有编辑权限的编辑会话的写操作不再返回 `PERM_DENIED_STATE`。
  4. 新状态不是 3 个枚举值之一的请求返回 `INVALID_STATE_TRANSITION`，原状态保持不变。
  5. 图纸状态为 `只读` 时没有编辑会话可写，不保留编辑权持有者；任何编辑会话的写操作都返回 `PERM_DENIED_STATE`。
  6. 把图纸切为 `单人编辑` 即锁定：切换后只有编辑权持有者可写，该图上其余编辑会话的写操作返回 `PERM_DENIED_STATE` 且应答含编辑权持有者。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 图纸 | String | 是 | — |
  | 原状态 | Enum(单人编辑/协同编辑/只读) | 是 | 只读 |
  | 新状态 | Enum(单人编辑/协同编辑/只读) | 是 | — |
  | 触发事件 | String | 是 | 人工切换、发布之一 |
- **来源**：§6.2.2.1.2.1.6

## 并发编辑策略

协同编辑下，一步编辑（一个撤销步）是一次**提交**。提交带着提交方的基线修订号，服务器据此判定先后；提交生效后图纸的基线修订号加 1，并以同一个修订号广播给该图的全部编辑会话（含提交方），不广播到其他图纸。**保存**指把本地图纸写入磁盘，不改变服务器上的状态，也不触发广播。

并发处置按「状态 × 事件 → 动作」表执行：

| 状态 | 事件 | 动作 |
| --- | --- | --- |
| 单人编辑 | 其他会话申请占用同一位号 | 拒绝申请并返回当前占用者、位号与到期时间 |
| 协同编辑 | 其他会话申请占用同一位号 | 授予首个申请者占用并向该图的全部编辑会话广播；其余申请被拒绝并返回当前占用者与到期时间（现行规则，以 `REQ-COLL-006` 验收 1 为准；是否改为排队等候见「未决事项」第 4 条） |
| 协同编辑 | 位号占用超时未续期，等待释放 | 释放占用、向该图的全部编辑会话广播并写入审计 |
| 协同编辑 | 写入一个被其他会话占用的位号 | 拒绝写入并返回占用者（`CLAIM_HELD`），提交方在本地撤回这一步 |
| 单人编辑 | 图纸被他人锁定（已有编辑权持有者），本端会话只读降级 | 本端编辑会话以只读建立并得知编辑权持有者；其写入被拒绝并返回 `PERM_DENIED_STATE` |
| 协同编辑 | 同一字段被 2 方修改，属性合并 | 基线修订号落后的一方让位（`OP_SUPERSEDED`），被覆盖的原值写入审计；双方基于同一修订且在并列窗口内到达时生成冲突条目，等待人工裁决 |
| 协同编辑 | 修改一个已被其他会话删除的对象 | 删除生效；修改被拒绝并返回删除前的值（`OBJECT_DELETED`） |
| 协同编辑 | 同一条管线的连接关系被基线落后的一方变更 | 拒绝并撤回（`STALE_BASE_REVISION`），由提交方按管线现状重做 |
| 协同编辑 | 删除已被其他对象引用的对象 | 拒绝删除并返回引用方清单（`OBJECT_REFERENCED`） |
| 只读 | 对已发布基线发起修改 | 拒绝写入（`PERM_DENIED_STATE`），须新建修订版本 |
| 协同编辑 | 会话心跳连续 6 次缺失 | 会话置为失效并释放其占用 |

并发模型有两条不变量：同一时刻同一张 `单人编辑` 图纸上最多 1 个编辑会话持有写权；同一张图纸的多个 `协同编辑` 会话共享同一 `基线修订号`。

### REQ-COLL-005 状态与事件的并发处置

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望并发事件按状态与事件的组合给出确定动作，以便多人同时编辑时行为可预期。
- **验收标准**：
  1. 状态 × 事件处置表覆盖 6 类事件：位号占用申请、占用超时释放、只读降级、属性合并冲突、删除被引用对象、发布后修改；每类事件至少 1 行且动作可判定。
  2. 同一时刻同一张 `单人编辑` 图纸上最多 1 个编辑会话持有写权；其后建立的编辑会话以只读建立并收到降级通知，通知含编辑权持有者（与 `REQ-COLL-007` 验收 1 是同一条规则，以该条为准）。
  3. 同一张图纸的多个 `协同编辑` 会话共享同一 `基线修订号`，任一编辑会话的提交生效后，该图全部编辑会话的基线修订号自动刷新为新的修订号。
  4. 协同会话中的撤销与重做只作用于本编辑会话自己的提交；其他编辑会话在其后对同一对象的修改保留，撤销后该对象上被别人改过的字段显示别人的值。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 状态 | Enum(单人编辑/协同编辑/只读) | 是 | — |
  | 事件 | String | 是 | 6 类事件之一 |
  | 动作 | String | 是 | 可判定结果 |
  | 基线修订号 | Integer | 是 | 同图协同会话一致 |
- **来源**：新增设计

### REQ-COLL-006 位号占用申请与超时释放

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望位号按单个粒度占用并在超时后自动释放，以便同一位号不被两人同时写。
- **验收标准**：
  1. 占用粒度为单个 `位号`；同一时刻同一位号只允许 1 个占用者，第 2 个占用申请被拒绝并返回当前占用者与到期时间。
  2. 占用有效期缺省 `300` 秒，服务器启动参数可调；到期未续期自动释放并写入审计日志 1 条；释放后其他会话可重新申请。
  3. 写入一个被其他编辑会话占用的位号被拒绝并返回 `CLAIM_HELD` 与占用者，提交方在本地撤回这一步；没有人占用的位号，有编辑权限的编辑会话不需要先占用即可写。
  4. 占用一条管线或管路的位号，同时拦住其他编辑会话对它的连接关系的变更（加管路、插管件、建或删页间连接符），这些变更返回 `CLAIM_HELD`。
  5. 占用的授予、释放、到期都向该图的全部编辑会话广播，广播含位号、占用者与到期时间；没有申请过这个位号的编辑会话，占用列表里随之出现或减少这一行。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 位号 | String | 是 | 占用粒度 |
  | 占用者 | String | 是 | 持有会话的用户 |
  | 会话 ID | String | 是 | 全局唯一，形如 `s-<UUID>` |
  | 有效期 | Integer | 是 | 缺省 300 秒，服务器启动参数可调 |
  | 到期时间 | DateTime | 是 | 只读 |
- **来源**：新增设计

### REQ-COLL-007 图纸锁定与只读降级

- **优先级**：必须
- **用户故事**：作为工艺设计人员，我希望图纸被他人锁定时自动降级为只读并看到占用者，以便不写冲突内容。
- **验收标准**：
  1. 编辑会话没有写权时以只读建立并收到降级通知，通知含拒绝级别、原因与编辑权持有者（有的话）；没有写权的情形有 3 种：用户没有编辑权限、图纸状态为 `只读`、`单人编辑` 图纸上已有编辑权持有者（即图纸被他人锁定）。
  2. 只读的编辑会话照常收到别人的修改；它的写操作被拒绝并返回该拒绝级别的码（`PERM_DENIED_ROLE`、`PERM_DENIED_PBS`、`PERM_DENIED_STATE` 之一），每次被拒绝的写入写入审计日志 1 条。
  3. 写权限的恢复是自动的，不需要人批准：图纸状态改变或编辑权易手后，服务器重新判定受影响的编辑会话并通知，被降级的编辑会话不用重连即恢复写权限；「重新申请写权限」是让客户端主动再问 1 次判定结果。
  4. 恢复前界面持续显示 `只读` 标记，断线期间不解除。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 图纸 | String | 是 | — |
  | 会话 ID | String | 是 | 全局唯一，形如 `s-<UUID>` |
  | 拒绝级别 | Enum(角色权限/PBS 节点 ACL/图纸状态) | 是 | 首个拒绝的级别 |
  | 原因 | String | 是 | 服务器给出的原因原文 |
  | 编辑权持有者 | String | 否 | 仅 `单人编辑` 图纸上有，返回给请求方 |
- **来源**：§6.2.2.2

### REQ-COLL-013 修改的提交与广播

- **优先级**：必须

## 冲突检测与解决

冲突分 3 类，判定条件与默认解决方式如下：

| 冲突类型 | 判定条件 | 默认解决 | 是否需人工 |
| --- | --- | --- | --- |
| 对象级 | 同一对象被一方删除、另一方仍提交修改 | 删除生效；修改被拒绝（`OBJECT_DELETED`），修改方收到通知与删除前的值 | 否 |
| 属性级 | 同一字段被 2 方写入不同值 | 按 `基线修订号` 判定，落后方让位（`OP_SUPERSEDED`），被覆盖的原值写入审计；并列时生成冲突条目 | 仅并列时 |
| 拓扑级 | 同一条管线的连接关系被 2 方变更 | 基线落后的一方被拒绝并撤回（`STALE_BASE_REVISION`），按管线现状重做；并列时生成冲突条目，裁决前拓扑不变 | 仅并列时 |

解决顺序固定为三段：① 不同字段的修改自动合并，互不覆盖；② 同一字段被两方修改时按 `基线修订号` 判定，落后的一方让位并由系统记录被覆盖的原值；③ 两个提交基于同一修订、且在并列窗口内到达（并列）时生成冲突条目进入冲突列表，由具有 `授权配置` 权限的用户裁决，裁决结果与双方原值写入审计日志。

并列窗口是服务器的启动参数，缺省为 `0`，即关闭：关闭时先到的提交生效，落后的让位并留痕，不产生冲突条目。窗口大于 0 时，基于当前修订的提交先暂存这么久；其间另一个编辑会话基于同一修订写同一字段且值不同，或变更同一条管线的连接关系，两个提交都不生效并生成 1 条冲突条目。

修改被拒绝的三种结局对应三个码，含义与提交方的处置见「错误码表」：`OP_SUPERSEDED`（让位，不要重发）、`OBJECT_DELETED`（对象已被删除）、`STALE_BASE_REVISION`（基线过期，按现状重做）。

## 编辑会话

本文档的「会话」都指编辑会话：一个用户在一张图纸上的一次连续编辑，靠心跳维持。它与 `REQ-PLAT-004` 的登录会话是两回事。编辑会话字段如下：

| 字段 | 类型 | 说明 | 约束 |
| --- | --- | --- | --- |
| 会话 ID | String | 会话全局标识 | 全局唯一，形如 `s-<UUID>` |
| 图纸 | String | 会话绑定的图纸 | — |
| 持有者 | String | 建立会话的用户 | — |
| 模式 | Enum | 会话的编辑模式 | ∈ 单人编辑、协同编辑、只读 |
| 状态 | Enum | 会话生命周期状态 | ∈ 活跃、失效、已接管 |
| 心跳间隔 | Integer | 客户端心跳周期，单位秒 | 缺省 15 |
| 超时阈值 | Integer | 判失效的无心跳时长，单位秒 | 缺省 90，服务器启动参数可调 |
| 基线修订号 | Integer | 会话共享的修订基线 | 同图协同会话一致 |

客户端缺省每 15 秒发送一次心跳；缺省连续 6 次（即 90 秒）无心跳的会话判 `失效`，其位号占用自动释放，它若是 `单人编辑` 图纸上的编辑权持有者，编辑权随之让出；同一图纸同一模式重新打开时可接管失效会话，接管写入审计。心跳间隔、超时阈值与占用有效期（15 秒、90 秒、300 秒）都是缺省值，不是固定值。

加入时编辑会话得到该图其他活跃编辑会话的名单，名单不含自己；后加入的一方从名单得知先到者，不另收通知；有编辑会话加入或离开时，其余的编辑会话得到通知。

仓库现有 `src/io/edit_lock.rs` 提供文件租约与外部变更指纹，它是不连服务器时对同一文件的编辑保护，只是图纸状态一级在单机上的实现细节，不构成本节的协同协议；协同由独立的协同服务器承担。

- **用户故事**：作为权限管理员，我希望同一操作在不同来源结论冲突时以拒绝为准，以便权限默认收敛到最小集。
- **验收标准**：
  1. 同一角色在用户级与角色级两级配置中对同一操作同时出现 `允许` 与 `拒绝` 时，判定结果为 `拒绝`。
  2. 未在权限矩阵中登记的操作默认 `拒绝`；登记前任何角色调用该操作被拒绝并返回 `PERM_UNKNOWN_OPERATION`。
- **数据与界面契约**：
  | 字段 | 类型 | 必填 | 约束 |
  | --- | --- | --- | --- |
  | 操作 | String | 是 | — |
  | 用户级判定 | Enum(允许/拒绝/未配置) | 是 | — |
  | 角色级判定 | Enum(允许/拒绝/未配置) | 是 | — |
  | 最终判定 | Enum(允许/拒绝) | 是 | 只读 |
- **来源**：新增设计
