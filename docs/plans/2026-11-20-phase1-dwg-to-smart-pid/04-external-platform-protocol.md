## 1. 当前验收总口径（代理标准与硬前提）

外部数字化交付平台为第三方黑盒系统，本仓库无其校验源码；已知 SPPID 原生产出的 `.pid` 与配套 `_Data.xml` / `_Meta.xml` 可通过其测试，但**平台的最低通过要求当前未知**，且送测机会少、单轮反馈周期以天计。为此锁定三条执行铁律：

1. **代理标准**：在最低要求摸清前，本平台导出的 XML 与 `.pid` 一律以「与已通过样本在格式和结构上逐项一致」作为代理验收标准；所有阶段报告必须写明「**外部平台最低要求未知，当前依据已通过样本代理标准判定**」。
2. **送测前强制本地门禁**：任何拟送测文件包在发出前，必须先通过 `#111` 严格厂商格式与结构校验器（`StrictVendor` 零违规）及 `#108` `xml_diff.py` 对照检查；当受控 SPPID 环境（`RES-06`）就绪后，还须通过预检第②关（SPPID 能打开 `.pid`）与第③关（SPPID 发布一致）。
3. **成组单变量「减法送测」**：绝不拿半成品盲测，也绝不一轮只测一个变量；每轮基于**同一张已知通过的最简真值样本**构造一组「每次只去掉一类要素」的受控变体，并随包附带一份**未改动的原样已通过样本作为阳性对照**（排除通道或批次环境干扰）。

## 3. 标准送测包结构契约

每次送测在证据目录 `$OCS_PID_EVIDENCE_DIR/submissions/round-<N>-<YYYYMMDD>/` 生成如下标准结构（清单只记相对路径与 SHA-256）：

```text
round-01-YYYYMMDD/
  00-control/               # 原样未改动的已通过样本（阳性对照，必须通过）
  01-var-xml-only/          # 变体 1：仅含 _Data.xml + _Meta.xml，不附 .pid
  02-var-no-topology/       # 变体 2：移除管线、端口、分支点、工艺点与连通 Rel
  03-var-minimal-attrs/     # 变体 3：仅保留 IObject(UID,Name) 与核心类型码表，其余业务属性置空
  04-var-plain-xml-format/  # 变体 4：去 UTF-8 BOM、改 LF 与 2 空格缩进（内容不变）
  05-var-synthetic-uids/    # 变体 5：将对象与管线 UID 替换为本平台确定性生成的新合法 UID
  submission-manifest.json  # 每份文件的 SHA-256、相对原样对照的精确改动说明、本地校验器结果
  receipt.json              # 收到外部回执后按固定字段回填
```

## 4. 两至三轮「减法送测」变体矩阵

### 第一轮：摸清文件组合、拓扑深度、格式敏感度与外来 UID 接受度（1 对照 + 5 变体）

| 槽位 | 相对原样样本去掉 / 改变了什么 | 期望探测暴露哪条平台硬要求 | 结果判读规则 |
|---|---|---|---|
| `00-control` | **零改动**（已知通过的最简真值样本原件） | 验证送测通道与批次基线正常 | 若它不过，说明送测方式或环境配置有误，本轮其余结果作废 |
| `V1-01` | **去掉 `.pid`**，只交 `_Data.xml` + `_Meta.xml`（及 PDF） | 平台到底读不读 `.pid` 二进制容器 | **若通过**：阶段一交付主线可直接以 XML+DWG/PDF 落地，`.pid` 降为可选增强！**若被拒**：确认 `.pid` 为硬门槛 |
| `V1-02` | **去掉管线合成与端口连通**：删去 `PIDPipeline`、`PIDPipingPort`、`PIDSignalPort`、`.BPT`、`.PPT` 及连通 `Rel`，只留设备/管件/仪表/管线段与 `DrawingItems` | 平台是否强检管网拓扑，还是只提取设备/仪表/阀门位号台账 | **若通过**：阶段 3 最小闭环无需被复杂管网连通阻塞；**若被拒**：连通拓扑升为最小闭环必做项 |
| `V1-03` | **去掉非核心业务属性**：保留全部接口骨架、`UID`、`Name` 与末级/分级码表值，将温度/压力/保温等扩展属性置 `""` | 平台是否有非空业务字段强校验 | 被拒报错点名的字段即为必填属性子集 |
| `V1-04` | **去掉厂商字节信封细节**：去 UTF-8 BOM、改 LF、改 2 空格缩进（XML 语义内容 100% 不变） | 平台用标准 XML 解析器还是按文本行/字节头硬匹配 | **若被拒**：证明 `#111` `StrictVendor` 字节级规则是真硬门槛 |
| `V1-05` | **重映射全图 UID**：按本平台 UID 分配器（32 位大写十六进制 + 派生端口/关系 UID）整体替换原样本 UID，并将容器 `DocName` 改为测试图号 | 平台是否校验「图纸/对象 UID 必须事先在某台 SPPID 数据库登记过」 | **若通过**：证明自研独立生成的全新 UID 完全可被平台接纳！ |

### 第二轮：按第一轮回执定向二分收敛（至多 4 变体）

- **分支 A（若 `V1-01` 被拒，确认平台读取 `.pid`）**：
  - `V2-01`：原样 XML + 经 `PidWriter::write_to` 流级无损重打包的 `.pid`（探测平台是否接受 `cfb` 字典序重打包容器）；
  - `V2-02`：最小空白种子 `.pid` 上仅增补 1 个设备记录 + 配套最小 XML（验证 `L5` 种子加增补方案在外部平台的可行性）。
- **分支 B（若 `V1-02` 或 `V1-03` 被拒且回执未给全字段名）**：
  - `V2-03`：保留管道连通（`Piping*`），仅去掉仪表信号连通（`Signal*`）；
  - `V2-04`：保留末级类型码表，去掉 `LEAF_LEVELS` 上级类型分级属性（验证 `#117` 上级类型链是否为平台硬要求）。

### 第三轮：单张简单存量 DWG 端到端闭环实测（检查点 C）

- 取 1 张简单存量 DWG → 本平台识别（`L3`）→ 升格统一模型（`L2`）→ 自研导出 `_Data.xml` + `_Meta.xml`（+ `.pid`）→ 本地预检全过 → 附 `00-control` 送外部平台终验。

## 5. 回执回填标准格式（`receipt.json`）

每次收到外部平台反馈后，按以下结构落盘至证据目录，并将结论摘要同步更新至同目录 `readings.md` 与 `plan.md`：

```json
{
  "round": 1,
  "submitted_at": "YYYY-MM-DD",
  "responded_at": "YYYY-MM-DD",
  "manifest_sha256": "<submission-manifest sha256>",
  "results": [
    {
      "slot": "00-control",
      "accepted": true,
      "error_code": null,
      "raw_message": ""
    }
  ],
  "conclusions": [
    "例如：V1-05 通过 -> 确认外部平台接纳自研生成的合规 32 位十六进制 UID"
  ]
}
```
