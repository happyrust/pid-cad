### ISSUE-L0-1 资料缺口没有登记，做决定时不知道"缺了会卡住什么"

**现状问题。**
- 现在能用的资料分散：94 对 SPPID 样本、两个备份包、728 个 `.sym`、12 个空白模板，但**没有一张表说明每项资料在哪、什么格式、缺了会阻塞哪个任务**。
- 解析库源码在本机没有（只有 cargo 缓存里的旧版本），也没有登记成"缺口"。
- 结果是：每次讨论"能不能开工"都要重新确认一遍资料状态。

**分析。**
- 资料缺口的性质不一样：有的缺了整条线停（解析库源码、外部平台信息），有的缺了只是降级（SPPID 截图、导出 DWG）。不区分就分不清优先级。
- 实施方案里已经定义了 17 项资料（RES-01…RES-17）和三种可得性标记，缺的只是核对与登记。

**解决方案。**
1. 按 RES-01…RES-17 逐项核对到"有 / 无 / 部分"。
2. 每项记录：路径（写进证据目录，不进仓库）、数量、格式、来源、日期、可得性标记。
3. 标 ⚠ 与 ✖ 的每项写清"缺了阻塞哪些任务"。

**执行路径。**
- 建一份 `资料现状表`（Markdown 表即可），放证据目录；仓库里只放不含客户路径的摘要。
- 表里每条与实施方案第 5 节的 RES 编号对齐，方便后续任务引用。

**验收。**
- 17 项都有状态。
- 每项标 ⚠/✖ 的都写明阻塞的任务编号。
- 摘要里不出现盘符、用户名、主机名。

**缺资料。** 无（本身就是清点资料）。

**对应任务。** L0-1（S）
**状态与解决记录。** **已完成（2026-11-20）**：已在同目录《智能PID平台-资料清单.md》完成 `RES-01`–`RES-17` 全量清点与状态标记（确认 `RES-01`–`RES-05`、`RES-07`、`RES-08` 已就位，明确标出 `RES-06` 受控环境与 `RES-15` 外部平台信息的阻塞与降级路径，全文零盘符/用户名）。

### ISSUE-L0-2 报告里的数字对不上具体文件，没法复现（GitHub [#107](https://github.com/happyrust/pid-cad/issues/107)）

**现状问题。**
- 仓库里已有读数文件（备份包计划那份），但那是针对备份包的；**阶段一的度量还没有"数字 ↔ 文件"的绑定**。
- 样本会更新（批次不同、图名会改），一旦换了文件，旧报告的数字就失去意义。

**分析。**
- 需要一层"语料清单"：每个逻辑名（`EXPORT_SET`、`SYMBOLS` 等）指向实际子目录，并记录每个文件的 SHA-256。
- 索引工具只用 Python 标准库，跨机器可用；未设置语料目录时跳过而不是失败，避免在没有样本的机器上把门禁弄红。

**解决方案。**
1. 定义 `corpus.manifest.json` 格式：逻辑名 → 实际子目录 → 文件清单 + SHA-256。
2. 写 `scripts/sppid/corpus_index.py`，两个子命令：`index`（生成）、`verify`（校验）。
3. 写 `scripts/sppid/corpus-layout.md` 说明约定布局。
4. 加一条"未设 `OCS_PID_CORPUS_DIR` 就跳过"的测试。

**执行路径。**
- 先定格式（一页），再写脚本（标准库，约 150 行），最后在真实语料上跑一遍生成清单。

**验收。**
- 对一个真实语料目录跑 `index` 生成清单，再跑 `verify` 通过。
- 故意改一个字节后 `verify` 失败并点名文件。
- 未设环境变量时退出码 0 且打印"未设置语料目录"。

**缺资料。** RES-02 ✔（导出样本集）。若样本尚未整理成约定布局，先用 `corpus.manifest.json` 写映射，不移动文件。

**对应任务。** L0-2（M）
**状态与解决记录。** **已完成（2026-11-20，提交 `538ec0112`，[#107](https://github.com/happyrust/pid-cad/issues/107)）**：落地 `scripts/sppid/corpus_index.py`、`scripts/sppid/corpus-layout.md`、`scripts/sppid/test_corpus_index.py`（先红 `8 failed` → 全绿 `167 passed`）；通过外置 `--manifest` 只读索引真实语料 `1,115` 个文件并通过校验、单字节篡改报错、未设环境变量退出码 `0` 与零绝对路径审计（详见同目录 `readings.md` §2）。

### ISSUE-L0-3 原始图与 SPPID 产出的对应关系没有建立（GitHub [#120](https://github.com/happyrust/pid-cad/issues/120)）

**现状问题。**
- 有 94 对 `.pid` + XML，有 94 个 DXF 和 94 个 PDF，但**没有一张表说明"哪个原始 DWG 对应哪几张图"**。
- 多页合并的原图拆分之后，图名与原始图名的对应关系也不明确。
- 数量上可能存在不一致（`.pid` 数与原图数不同），现在没人核对。

**分析。**
- 没有对应关系，"识别准确率"就没有分母：不知道哪些图该有、哪些是模板图或空图。
- 文件名前缀能解决大部分配对（`<图名>.pid` / `_Data.xml` / `_Meta.xml` 同名），DXF 与 PDF 也能按图名匹配；难点只在多页合并与改名。

**解决方案。**
1. 按文件名前缀做初配。
2. 用图名与 DXF/PDF 匹配，交叉验证。
3. 多页合并的原图：用拆分对照表（若有）或按图名与文字相似度做候选，人工确认。
4. 输出 `corpus.manifest.json` 的 `correspondence` 段 + 一份人可读 CSV。

**执行路径。**
- 先跑自动配对，把"自动确定"和"需要人工确认"分成两栏；人工只处理后者。

**验收。**
- 每张 `.pid` 都有 `_Data.xml` 与 `_Meta.xml`。
- 无法对应的项单列并写明原因。
- 数量不一致时（例如 `.pid` 多于原图）在报告里点名。

**缺资料。** RES-02 ✔；RES-16 ⚠（原始图对应关系）。缺 RES-16 则按相似度候选并标"待确认"，无法确认的不进识别度量的分母。

**对应任务。** L0-3（M）
**状态与解决记录。** **已完成（2026-11-20，[#120](https://github.com/happyrust/pid-cad/issues/120)）**：落地 `scripts/sppid/{corpus_correspondence,test_corpus_correspondence}.py`（先红后绿，`pytest` `179 passed`）；94 套三件套 100% 齐全，DXF/PDF 配对 `84` 精确 + `10` 近形字候选，自动检出剔除 `4` 份 `0` 字节空 DXF 锁定 `90` 张有效分母，详见 `readings.md` §9。

### ISSUE-L0-4 没有度量工具，"像不像"只能靠肉眼（GitHub [#108](https://github.com/happyrust/pid-cad/issues/108)）

**现状问题。**
- 现在判断导出对不对，靠看图和零散比对，没有可复现的数字。
- 仓库里有 PDF 比对脚本（备份包计划），但没有：① 两份 XML 的逐项比对；② 识别结果对参考 XML 的召回与精确。

**分析。**
- 三类度量对应三种验收：XML 对不对（结构 + 内容）、识别准不准（召回/精确/配对）、显示像不像（覆盖率/多画长度/文字对上条数）。
- 差异清单必须"一行一个差异、可解释"，否则没法进白名单门禁。

**解决方案。**
1. `scripts/sppid/xml_diff.py`：两份 `_Data.xml` 按对象 UID 对齐，比对类型、接口集、属性集与取值、关系集合；输出新增/缺失/属性不同/关系不同四类差异。
2. `scripts/sppid/legend_vs_xml.py`：识别结果（`PIDLEGEND EXPORT` 的 JSON）对参考 XML，算符号召回、精确、位号配对准确率。
3. `scripts/sppid/render_vs_pdf.py`：复用仓库已有的 PDF 比对方法（覆盖率、多画长度、文字对上条数）。

**执行路径。**
- 每个脚本先做"自己比自己 = 零差异"的自检，再做"故意改坏"的测试。

**验收。**
- 三类脚本各自有：同文件零差异、改一个属性/删一个对象/删一条关系各报一条预期差异。
- 输出格式固定（表头固定、一行一个差异）。
- 只用标准库；`python -m pytest scripts/sppid -q -p no:cacheprovider` 通过。

**缺资料。** RES-02 ✔。

**对应任务。** L0-4（M）
**状态与解决记录。** **已完成（2026-11-20，[#108](https://github.com/happyrust/pid-cad/issues/108)）**：落地 `scripts/sppid/{xml_diff,legend_vs_xml,render_vs_pdf,test_metrics_108}.py`（共用 TSV 固定表头，先红 `5 failed` → 全绿 `176 passed`）；合成管线支持按唯一 `Name` 对齐并预留 `--allowlist` 白名单；全量 `94` 套 XML/PDF 自检与 `11` 套厂商验收记录核对全部零差异通过（详见 `readings.md` §5）。

### ISSUE-L0-6 门禁基线没在当前 `main` 上量过（GitHub [#109](https://github.com/happyrust/pid-cad/issues/109)）

**现状问题。**

- 读数文件里有四组数字 + 日期 + 提交号。
- 后续任务按它判"不增加"。

**缺资料。** RES-08（运行时生成）。

### ISSUE-L0-7 外部平台的验收口径没有落地成可执行流程（GitHub [#121](https://github.com/happyrust/pid-cad/issues/121)）

**现状问题。**
- 已知：外部平台是其他单位的数字化交付平台，我们没有它的代码；已知 SPPID 产出的 `.pid` 与配套 XML 能通过；**最低要求未知**。
- 已知：送测次数很少、一次反馈要几天。
- 但没有把这些变成"送什么、怎么送、怎么判、怎么回填"的流程。

**分析。**
- 因为无法本地复现平台检查，只能用"与已通过样本一致"作代理标准，再用 SPPID 做送测前预检。
- 次数少意味着不能逐个变量试；必须每轮送一组变体（每份只去掉一类内容，另带一份原样样本作对照），一轮摸多条要求。

**解决方案。**
1. 整理外部平台信息（交付规范、过往回执、已通过样本清单、收什么文件、一次送几份、是否逐份返回）。
2. 定义送测包结构：一组变体 + 一份原样对照 + 一份说明（每份改了什么）。
3. 设计"减法送测"变体清单，控制在两三轮内。

**执行路径。**
- 先按"去掉管线连通""去掉某类接口""只留符号与位号"三类设计第一轮。

**验收。**
- 口径写成一页。
- 每轮变体列出"去掉什么、期望暴露哪条要求"。
- 缺信息处明确标"待补"。

**缺资料。** RES-15 ✖（阻塞"精确口径"）。缺则按代理标准执行，所有报告写"最低要求未知"。

**对应任务。** L0-7（S）
**状态与解决记录。** **已完成（2026-11-20，[#121](https://github.com/happyrust/pid-cad/issues/121)）**：落盘同目录 `04-external-platform-protocol.md`（见 `readings.md` §10），明确「最低要求未知，按已通过样本一致代理标准执行」，列出 `RES-15` 五项待补信息、三轮单变量减法矩阵及 `receipt.json` 标准格式。
