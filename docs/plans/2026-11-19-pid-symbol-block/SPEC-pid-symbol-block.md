# SPEC：`.pid` 图例导入成图块（`pid-symbol-block`）

> 状态：**已确认**（2026-11-19）。用户对 §9 六个问题的答复：「按你推荐的方案做。没有明确推荐的，你结合当前情况选最合适的继续，并简要说明理由。」各问题的结论见 §9；确认之后读代码改准的四处见 §11。基线 `main @ 260aabac7`。
> 计划和任务清单：同目录的 `plan.md`、`todo.md`。
> 依据：用户要求（2026-11-19）「现在我们对于图例现在还没有按照一个快的方式去选中」「图例是 pid 文件里的信息，一个图例就是一个整体的图块」；需求 `REQ-MIG-008`（`docs/pid-platform/requirements/90-migration-and-interop.md`）。
> 共用约定见 `docs/plans/2026-11-16-pid-dev-spec/01-shared-conventions.md`。
> 文中的数字，除另有说明，都是在样例图 `pid-test-data\backup-plant-data\00\00\L M井场 注采阀组工艺及自控流程图.pid` 上，用 `71748d8fa` 的发行版以无界面方式（`--serve`）量得的；量法见 §2.6。

## 1. 目标

打开一张 `.pid` 图纸后，图面上的每个图例是一个图块（块引用）：

1. 在图例的任意一笔上点一下，选中的是整个图例；悬停高亮、框选、移动、复制、旋转、删除也都按整个图例算。
2. 图纸旁边没有 `_Data.xml` 时同样成立。工厂备份里的图纸都是这种情况。
3. 画面和出图与现在逐笔相同。
4. 选中一个图例，属性面板显示这个图例的一份 P&ID 信息。
5. 另存为 DWG 再打开，图例还是图块。

本规格只管导入器把图例建成什么，以及因此要跟着改的几处：视图过滤、属性面板、图例识别、导入摘要。

### 1.1 前提

写规格时采用的理解（确认规格时用户没有提出不同意见）：

1. 「图例」指 `.pid` 文件里的符号实例：阀门、仪表圆圈、法兰、设备、带符号的标注。不是图框里的图例说明表，也不是在 DXF、DWG 图纸上识别出来的符号。
2. 「快的方式选中」指点一下就选中整个图例。按位号查找、按种类批量选中不在这句话里（见 §9 的 Q5）。
3. 「图块」就是 CAD 的块引用，存成 DWG 后在别的 CAD 软件里也是块。
4. 除了能整体选中，其他都不该变：画面、出图、图层开关、属性面板里能看到的内容。
5. 已经另存成 DWG 的旧图不处理；要整体选中，重新打开原来的 `.pid`。

## 2. 现状

### 2.1 文件里是怎么存的

- 一个图例在 `.pid` 里是一条符号实例记录：`pid_parse::PidGraphicKind::SymbolInstance { insertion, symbol_path, rotation, scale, definition }`，即插入点、旋转、比例，加一个指向定义的引用。文件本身就是按「定义加实例」存的。
- 定义的图形有三个来源，按顺序取（`src/io/pid/symbols.rs`）：图纸自己缓存的本体（`cached_body_entities`，存的是这个实例改过尺寸之后的样子）；符号库里的 `.sym`（`library_body_entities`）；都没有时画一个标记圆点。

### 2.2 导入时做了什么

- `src/io/pid/build.rs` 的 `build_document_entities` 逐条处理图形记录。对一条符号实例，`build_entities` 返回它的全部笔画，坐标已经换到图纸上；循环里再逐笔上色、定图层、挂记录，然后一笔一笔 `doc.add_entity`。
- 在这个循环里还知道哪些笔画属于同一个图例；加进文档之后，没有任何东西记着这件事。
- 每个图例另加一条写着符号名的文字，放在 `PID-SYMBOL-LABEL` 图层，这个图层默认关闭。
- 每一笔都挂一份 `PID_SEMANTICS` 扩展数据（`src/io/pid/metadata.rs` 的 `attach_pid_metadata`）：

| 键 | 什么时候有 |
|---|---|
| `sheet_layer`、`sheet_layer_oid`、`role`、`style`、`extent`、`driving`、`instance` | `.pid` 里有就有 |
| `class`、`label`、`oid`、`resolved` | 只有图纸旁边有 `<图名>_Data.xml` 时才有 |

结果是点一下只选中一笔。样例上 592 个图例散成了 4,477 个图元：线 3,105、文字 622、圆 432、圆弧 215、填充 93、多段线 10。

样例上每个图例的笔画都出自同一条记录：592 个图例的图元在文档里各是连续的一段，最后一个是符号名文字。所以「一条符号实例记录画出的全部图元」就是「一个图例」，不需要再靠几何去猜。

### 2.3 现有的几条路为什么不够

| 办法 | 问题 |
|---|---|
| 按每笔上的 `oid` 归并 | 只带 `.pid` 时，样例的 10,275 个图元里 0 个有 `oid`。带上 `_Data.xml` 有 4,384 笔有，但打开要 8–13 秒（不带是 1.8–2.7 秒），而工厂备份里没有这个文件 |
| 图例识别（`PIDLEGEND`，`src/io/pid_legend/`） | 是给 DXF、DWG 图纸写的，在这张图上认出 0 个符号 |
| 手工编组（`GROUP`） | 能整体选，但要一个一个编，一张图 592 个 |

### 2.4 程序里已有、可以直接用的

- 块引用在点选、悬停、框选、移动、复制、旋转、删除、撤销、存 DWG 里都是一个对象。
- 块里的图元按标准规则显示（`src/scene/cache/block_cache.rs` 的 `append_defn_entity`、`src/scene/render_graph.rs` 的 `block_member_layer_hidden`）：在 0 层的随引用所在的图层；所在图层关闭或冻结的不画；带 `invisible` 标志的不画。引用自己不显示时（带 `invisible`，或所在图层关闭、冻结），块里的图元都不画。
- 属性面板对带 `PID_SEMANTICS` 的块引用已经会显示 `[P&ID]` 一栏（`src/scene/view/dispatch.rs` 的 `properties_sectioned`）。
- 视图过滤 `PidViewFilter::apply`（`src/io/pid_view_filter.rs`）遍历文档里的全部图元，按图元自己的 `sheet_layer=`、`role=` 设 `invisible`；没写的键按「开」算。「全部图元」包括块定义里的图元（`Document::entities_mut`）。开关之后程序会让全部图块重画（`src/app/layers.rs` 的 `after_pid_view_switch` 调 `bump_geometry`）。
- 把外来的名字洗成合法块名：`scene::sanitized_table_name`。
- `SELECTSIMILAR`、`QSELECT` 已有。

### 2.5 一张图上有多少种图例

样例的 592 个图例只用了 58 种符号。块定义怎么分，数量差别很大：

| 分法 | 定义数 | 说明 |
|---|---|---|
| 一：每个图例一个定义 | 592 | |
| 二：画出来完全一样的共用一个，引用只管位置 | 118 | 按本体外框对齐统计的；按插入点对齐的数要在实现时复核（实现后量得 119，见 §11） |
| 三：同一种符号共用一个，旋转、镜像、比例交给引用 | 62 | 58 种符号里有 4 种各有两种画法 |

用得最多的几种（个数；分法二、分法三下的定义数）：DCS Func Access in Prime Loc 82（2；1）、Ball Valve Type 2 50（7；1）、2 Way Generic Body Type 1 36（4；1）、Flange Type 2 36（6；1）、Insulation Joint 27（5；1）。

### 2.6 试验

为了知道改成图块会碰到什么，在样例上用程序自带的建块操作（自动化接口的 `block_define`）把 592 个图例逐个转成了块引用，按分法一。

| 项 | 结果 |
|---|---|
| 建块 | 592 个，0 个失败 |
| 出图（SVG，297×210） | 转换前后各 17,627 个图形元素，坐标按 0.01 取整后逐个比较，只在一边出现的 0 个 |
| 另存 DWG | 499,568 → 848,297 字节（多 70%）；再打开用 66 ms，592 个块引用都在 |
| 属性面板 | 给块引用写上 `PID_SEMANTICS` 后，显示 `[P&ID]` 一栏：角色、本体尺寸、图纸图层、图层 OID |
| 图例识别 | 转换前认出 0 个符号；转换后把 592 个块全部列成了「未知块」。要处理，见 §4.5 |

没验证到的：

- 鼠标点选。无界面方式下视口大小是 0×0，点选落不到要点的图元上。这一条放到实现时的单元测试里验证，写法照现有的点选测试（直接设视口大小）。
- 分法二、分法三下的出图。试验只做了分法一。
- 试验里图元留在原来的图层，没有试「块里的图元放 0 层」。

量法：只带 `.pid` 时分不出哪些笔画是一个图例，所以图例的归属是借同一张图带 `_Data.xml` 的那份按 `oid` 归并得到的；两份图的图元句柄和类型逐个相同，归属可以直接套用。试验脚本在仓库外，没有入库。

## 3. 数据格式

### 3.1 一个图例在图里是什么

一个块引用，加它指向的块定义。

**块引用**（在模型空间，一个图例一个）

| 项 | 取值 |
|---|---|
| 插入点 | 符号实例记录的插入点，换算到图纸坐标后的值 |
| 旋转、比例 | 0、1（按分法二，见 §3.2） |
| 图层 | 图例的笔画现在所在的图层：记录带作者的图纸图层名时就是这个名字（文件里隐藏的图层，这个图层本身是关的）；不带名字时是 `PID-SYMBOL`，不带名字又隐藏时是 `PID-HIDDEN`。只画了符号名文字的图例，引用放在那条文字现在所在的图层：`PID-SYMBOL-LABEL`，不带名字又隐藏时是 `PID-HIDDEN` |
| 扩展数据 | 一份 `PID_SEMANTICS`，见 §3.4 |

**块定义**

- 内容是这个图例现在最终加进文档的那些图元（上色、字高、对齐、文字换行这些后处理都做完之后的），坐标减去插入点。
- 块里图元的图层：先按现在的规则算出它本来会落在哪个图层；和引用的图层相同的，放 0 层，这样它们随引用所在的图层开关、冻结和取色；不同的，留在本来的图层。颜色、线宽、线型的取值不变。
- 按这条规则，笔画和标记圆点在 0 层；记录带图层名时填充也在 0 层，不带时填充留在 `PID-FILL`（现在就是这样分的）。
- 写着符号名的那条文字也在定义里，留在 `PID-SYMBOL-LABEL` 层（默认关闭），所以移动图例时它跟着走。只画了符号名文字的图例，引用本身就在这一层，那条文字和引用同层，所以放 0 层。
- 块里的图元只带一个键 `role=`，见 §3.5。

下面两种情况同样处理，这样「块引用数等于画出的图例数」总成立：

- 没有本体、画成标记圆点的图例：圆点和符号名文字成一个块。
- 标注类图例里本体只有锚点十字的（现在只画符号名文字，样例上 27 个）：成一个块，里面只有那条文字（§9 的 Q4）。引用在 `PID-SYMBOL-LABEL` 层，这个图层默认关闭，所以和现在一样默认看不见、也选不到。

边框模板（`.igr`）里的符号实例不成块，照旧是散图元（§8）。它们走的是 `src/io/pid/template.rs` 里另一个循环（`overlay_template`），画出来的是图框的笔画：角色是 `frame`，在 `PID-FRAME` 层，没有符号名文字，也没有标记圆点。

### 3.2 块定义怎么共用

用 §2.5 的分法二（§9 的 Q1）：

- 两个图例的定义内容完全一样，就共用一个定义。「完全一样」指符号名相同，并且块里每个图元的类型、坐标、颜色、线宽、线型、图层、文字内容和字型字高都相同；坐标按 0.000001 mm 取整后比较。
- 共用的定义存的是第一个图例的图元。其余图例因此与现在的画法最多差 0.000001 mm。
- 引用的旋转是 0、比例是 1。文字的朝向、镜像后的可读性、圆在不等比缩放下的画法，都还是导入器现在算好的结果，不交给块引用去变换。

### 3.3 块名

- `SPPID_<符号名>`。符号名取 `symbol_name(symbol_path)`，用 `scene::sanitized_table_name` 洗掉块名不允许的字符。文件没给符号路径时用 `SPPID_SYMBOL`。
- 同一种符号有几种画法时，第一种用上面的名字，之后的依次加 `_2`、`_3`……，按在文件里第一次出现的顺序。加完序号的名字已经被占用时继续往后数。
- 同一个文件导入两次，块名相同。
- 前缀是为了不和调色板的符号块（`PID_SYM_<类>_<符号>`）、模板里的块、用户自己的块重名。见 §9 的 Q2。
- 块名只是给人看的。程序里判断一个块引用是不是导入的图例、是哪种符号，一律看引用上的记录（§3.4），不看块名。

### 3.4 块引用上的记录

应用名还是 `PID_SEMANTICS`，格式还是一条字符串一个 `键=值`。

| 键 | 值 | 什么时候有 |
|---|---|---|
| `role` | `symbol` | 总有，只画了符号名文字的图例也是 |
| `symbol` | 符号名，洗之前的原样 | **新增**。文件给了符号路径时 |
| `sheet_layer`、`sheet_layer_oid` | 同现在 | 记录带图层引用时 |
| `style` | 同现在 | 同现在 |
| `extent` | 同现在：本体的外框尺寸 | 同现在 |
| `driving`、`instance` | 同现在 | 同现在 |
| `class`、`label`、`oid`、`resolved` | 同现在 | 只有旁边有 `_Data.xml` 时 |

现在这些键每一笔上各有一份；改后一个图例只有引用上的这一份。

### 3.5 块里图元上的记录

只写 `role=`，取值同现在（`symbol`、`fill`、`symbol-label`）。其余的键是「这一次放置」的信息，而定义可能被多个图例共用，所以不写在定义里。

留着 `role=` 是为了视图过滤能单独关掉图例里的填充或符号名（§4.3）。

### 3.6 没有变的

- 不是符号实例的记录（线、文字、独立的填充、点标记、图框）照旧是散图元，记录照旧。
- 不新增图级记录，不新增图层。一张图是不是按本规格导入的，看有没有带 `role=symbol` 的块引用。

## 4. 行为

### 4.1 选择和编辑

- 点选、悬停、框选、窗交：图例是一个对象。
- 移动、复制、旋转、镜像、删除、撤销：按整个图例。复制出来的也是一个块引用，记录原样带过去。带 `_Data.xml` 导入的图上，复制品会和原件有相同的 `oid`、`label`；现在复制散笔画时也是这样。
- 夹点只有插入点一个。有些符号的插入点不在本体上（标注类），夹点也就不在本体上。
- 炸开（`EXPLODE`）后变回散图元，引用上的记录随引用消失，散图元上只剩 `role=`。
- 共用一个定义的图例，在块编辑器里改定义会一起变。这是块本来的行为。
- 对象捕捉：改之前能捕到的图例笔画的端点、圆心，改之后还能捕到。

### 4.2 显示和出图

与基线逐笔相同（§6 第 4 条）。相机取景范围（`accumulate_bounds`）不变。

### 4.3 图层和视图过滤

- 关掉一个图纸图层：这一层的图例整个不显示（引用被设成 `invisible`）。
- 关掉角色 `symbol`：全部图例不显示。
- 关掉角色 `fill`：图例里的填充不显示，轮廓还在（块里带 `role=fill` 的图元被设成 `invisible`）。
- 打开 `PID-SYMBOL-LABEL` 图层：符号名显示在每个图例旁边；只画符号名的图例这时才看得见、选得到。隐藏图层上的图例不受影响：引用不显示，块里的符号名也就不显示。
- 过滤改了块里图元的 `invisible` 之后，画面立即跟着变。现有的开关处理在改完之后会让全部图块重画（§2.4），不需要另加代码，用测试钉住。
- 图层管理器的图纸图层视图里，每一行的数字是带这个键的对象数。改后，图纸图层那几行里一个图例算 1 个（只有引用带 `sheet_layer=`）；角色那几行里，引用算 1 个，块里的图元按定义各算 1 个（共用的定义只算一次）。行还是那些行，数字会变小。
- 过滤状态的存取（`PID_VIEW_FILTER` 记录）不变。

### 4.4 属性面板

- 选中一个图例：`[P&ID]` 一栏显示角色、符号名（新增一行）、本体尺寸、驱动尺寸、图纸图层、图层 OID；带 `_Data.xml` 时另有类型、位号、匹配方式。
- 选中几个图例：照现有的多选规则，取值不同的显示 `*VARIES*`。
- 块引用自己的几栏（位置、比例、名称、旋转）照常显示。

### 4.5 图例识别

`PIDLEGEND` 的块符号那一遍（`src/io/pid_legend/mod.rs`）遇到带 `role=symbol` 记录的块引用时跳过：既不算认出的符号，也不算未知块。块里的文字不再算散字：试验里样例的散字数从 1,580 变成了 958。

把它们按符号名列成认出的符号是另一件事，见 §9 的 Q3。

### 4.6 导入摘要

- `ImportSummary` 现有各项计数的数值不变。`drawn` 仍然数画出的图元：块里的图元算，块引用本身不算。
- 新增两项：`symbol_blocks`（导入器建的块引用数，也就是画出了图元的符号实例数）、`symbol_definitions`（导入器建的块定义数）。边框模板里的符号实例不算。

## 5. 对外接口

- 没有新命令，没有新系统变量，没有新依赖。
- 自动化接口的 `entities`、`query` 里，图例从一组线、圆、文字变成一个 `Block Reference`；`pid_legend` 的结果按 §4.5 变。依赖这些输出的脚本要跟着改。
- 存 DWG、DXF 用的是标准的块和扩展数据，不需要新的读写代码。

## 6. 成功标准

1. 样例导入后，模型空间里带 `role=symbol` 的块引用数等于文件里画出的符号实例数（样例 592）；模型空间里没有 `role` 为 `symbol` 或 `symbol-label` 的散图元。
2. 在一个图例的任意一笔上点一下，选择集里只有这个图例的块引用；悬停高亮的是同一个对象；框住整个图例选到 1 个对象。
3. 第 1、2 条在只有 `.pid` 时成立。旁边有 `_Data.xml` 时，引用上另有 `class`、`label`、`oid`、`resolved`，取值与基线写在笔画上的相同。
4. 出图不变：样例导入后出的 SVG，与基线导入后出的 SVG 相比，图形元素个数相同，坐标按 0.01 取整后只在一边出现的元素为 0 个。相机取景范围相同。
5. 关掉一个图纸图层，这一层的图例不显示，再打开恢复；关掉角色 `fill`，图例里的填充不显示而轮廓还在；打开 `PID-SYMBOL-LABEL`，符号名出现，移动图例后符号名跟着走。
6. 选中一个图例，属性面板的 `[P&ID]` 一栏里有角色、符号名、本体尺寸、图纸图层，没有 `*VARIES*`。
7. 移动、复制、删除、撤销按整个图例；复制出来的是一个带同样记录的块引用。
8. 另存 DWG 再打开，块引用数、每个引用的记录、出的图都与保存前相同。（2026-11-22：其中「出的图与保存前相同」按字面不成立。这一条是按下面的说法收的：块引用数、每个引用的记录、图形元素的个数和次序与保存前相同；线宽取 DWG 存得下的最接近的标准值。见 §11 最后的「成功标准第 8 条怎么收」。）
9. 图例识别不把导入器建的块报成未知块。
10. 导入摘要里现有计数的数值与基线相同；`symbol_blocks` 等于画出的图例数；同一个文件导入两次，块名和 `symbol_definitions` 相同。
11. 样例只带 `.pid` 的导入用时（3 次取中位数）不超过基线同机中位数的 1.1 倍；另存 DWG 的大小不超过基线的 1.7 倍（试验里分法一的值）。
12. 共用约定里的各项门禁不变差。

## 9. 问题和结论

六个问题都已按建议定下（2026-11-19，用户答复见文首）。下表是提问时的原文，结论和定下之后核实的内容列在表后。

| # | 问题 | 建议 |
|---|---|---|
| Q1 | **块定义怎么分。** §2.5 的三种分法，样例上分别是 592、118、62 个定义 | 本期用分法二。画面由构造保证不变；定义数是分法一的五分之一；块名是符号名，看得懂。分法三最像原文件的存法，但要让块引用去做旋转、镜像和缩放，文字朝向、不等比缩放下的圆、按放置重新上色这三处都可能和现在画的不一样，要另做一轮对图。引用上的记录三种分法相同，以后要换不影响已有的约定 |
| Q2 | **块名要不要带前缀 `SPPID_`。** 不带的话块名就是 `Ball Valve Type 2` 这样的符号名 | 带。不和调色板的符号块、模板里的块、用户自己的块重名，在块列表里也能一眼分出来 |
| Q3 | **图例识别怎么对待这些块。** 跳过，还是按符号名列成认出的符号 | 本期跳过。图例识别是给 DXF、DWG 图纸用的；`.pid` 图例的种类已经写在引用的 `symbol=` 上。要让统计、清单用上它们，另立一项 |
| Q4 | **只有符号名文字的标注类图例要不要也成块。** 样例上 27 个；符号名图层关着时看不见，也点不到 | 成块。规则统一，块引用数和文件里的图例数对得上 |
| Q5 | **「选中同一种图例」本期要不要做。** | 不做新命令。画法相同的图例块名相同，`SELECTSIMILAR` 按名称比对时能一起选中（它比的属性里有没有块名，实现时确认）；按 `symbol=` 选出全部同种的，放到后续 |
| Q6 | **要不要在需求文档里补一条。** `REQ-MIG-008` 只说「显示图面」，没说图例能整体选中 | 补一条验收标准。改 `docs/pid-platform/` 要先问，所以列在这里 |

结论：

- **Q1** 分法二。**Q2** 带前缀 `SPPID_`。**Q3** 图例识别跳过。**Q4** 成块，引用放在 `PID-SYMBOL-LABEL` 层（§3.1）。
- **Q5** 不做新命令。已核实：`SELECTSIMILARMODE` 的默认值是 130，比的是图层和名称（`docs/wiki/sysvars/SELECTSIMILARMODE.md`）。所以在同一个图层上、画法相同（块名相同）的图例，选中一个后用 `SELECTSIMILAR` 能一起选中。同一种符号里朝向或尺寸不同的画法，块名带不同的序号，不会一起选中；要按符号名全选，等后续按 `symbol=` 选择的那一项。
- **Q6** 给 `REQ-MIG-008` 补一条验收标准，随实现一起改（`todo.md` 的 SB-8）。

## 11. 确认之后改准的地方，和实现记录

确认之后、写计划之前读了导入器和显示的代码，下面四处与草案（`5171d197b` 的版本）不同，正文已经改过来：

1. **图层规则**（§3.1）。草案写「引用在作者的图纸图层，隐藏的在 `PID-HIDDEN`；笔画放 0 层」。现状其实分三种（`src/io/pid/build.rs` 循环里定图层的那一段）：记录带图层名时，笔画和填充都在这个图层，隐藏的图层本身是关的；不带时笔画在 `PID-SYMBOL`、填充在 `PID-FILL`；不带又隐藏时全部在 `PID-HIDDEN`。符号名文字总在 `PID-SYMBOL-LABEL`，只有不带又隐藏时在 `PID-HIDDEN`。正文改成「引用放在笔画本来的图层；块里的图元和引用同层的放 0 层，不同层的留在本来的图层」，这样每个图元受哪个图层管与现在相同。
2. **只画符号名的图例**（§3.1、§4.3）。引用放在 `PID-SYMBOL-LABEL` 层。放在别的图层会出现一个看不见却能被框选到的对象。
3. **边框模板里的符号实例**（§3.1、§8）。不成块，理由见 §8。
4. **视图过滤**（§2.4、§4.3、§7）。不需要改代码：遍历全部图元本来就包括块里的图元，开关之后本来就会让全部图块重画。只加测试。图层视图各行的数字会变小（§4.3），草案里没有提。

实现中与本规格不一致的地方，按任务编号记在下面。

**SB-2**（2026-11-19）

1. **定义数**（§2.5、§9 的 Q1）。分法二在样例上实测是 119 个定义，不是估的 118 个。估的时候按本体外框对齐、坐标取 4 位小数；实现按插入点对齐、取 6 位（§3.2）。118 这个数没有复现，原脚本没有重跑。换成更粗的比法还能合并的只有两处：`Flange Type 2` 有 1 个图例的本体和另外 19 个差 0.000027（源数据如此）；`Item Note & Label` 只画符号名，文字相对插入点有两种位置。`pid-test-data` 下能导入的 151 个文件共 28,322 个块引用、8,433 个定义，这两类共 55 个定义。
2. **实心填充的图案原点不参加比较，也不留在定义里**（§3.2）。acadrust 平移填充时总把图案原点写进填充的扩展数据（应用名 `ACAD`），这个值随位置变；留着它，画法相同、位置不同的图例都不共用。所以没有图案线的填充，平移之后恢复平移前的那条记录（原来没有就删掉）。带图案线的填充保留平移后的原点，因为图案靠它对齐。导入器现在只产生实心填充（`Hatch::new()`，不设图案），所以带图案线的这一支现在走不到，只有单元测试覆盖。
3. **画不出任何图元的符号实例不建块**（§3.1）。和改之前一样什么都不留，「块引用数等于画出的图例数」仍然成立。

**SB-2b**（2026-11-19）

1. **块里的圆、圆弧、椭圆按块内次序叠放**（§4.2、成功标准第 4 条）。图例成块之后，样例上 `Set Fire Point` 的填充和圆的轮廓换了先后。原因不在导入器，在块的显示代码：块展开时（`src/scene/cache/block_cache.rs` 的 `emit_wire`），纯的圆、圆弧、椭圆成员走单独的一条路，深度只取引用自己的位置，不带它在成员里的次序；线、多段线、填充、文字都带。结果是排在块前半段的填充总在曲线下面，后半段的总在上面，正中间的和曲线并列，并列时出图先画填充。改成曲线和别的成员用同一个算式。这处改动对所有图块生效，DWG、DXF 图纸上的也在内；全量测试没有一个因此变红。按规则推算，`pid-test-data` 能导入的 151 个文件、8,433 个定义里，改之前先后会被换的有 38 个定义（142 个引用、35 个文件），全是 `Set Fire Point` 和 `Set Fire Point_2`，都是轮廓画到了填充上面。
2. **成功标准第 4 条的比法看不出先后对调**（§6）。它是按集合比：元素个数相同，坐标按 0.01 取整后只在一边出现的元素 0 个。上面那一处两边的元素完全相同，只是先后换了，按这个比法是过的。所以检查点一、SB-9、SB-10 的对图多比一项：按画的先后逐个比，元素和它用的笔都要相同。
3. **SB-2 的程序出图，同一支笔的线先后不固定**。用 SB-2 的程序给样例连出两次图，有 2 段（共 6 个元素）先后不同，都是同一支笔的线，画出来一样；只量了这两次。SB-2b 的程序连出 5 次，SVG 逐字节相同。原因没有单独查。

**SB-2c**（2026-11-19）

1. **出图按窗口筛图元时，贴在窗口边上的块副本笔画会被丢掉**（成功标准第 4 条）。全部样例对图时，能出图的 151 张里有 1 张少一笔：`集注站 放空火炬系统工艺及自控流程图.pid`，图面最左边那个 `Off-Unit SQ` 图例的左边线。原因不在导入器，也不在 SB-2b（SB-2 的程序同样少这一笔）：出图先按窗口筛图元（`src/app/update/file.rs` 的 `area_plot_job`），比的是单精度的外框和取成单精度的窗口；同一个块的第二个及以后的引用是照第一个（原件）挪过去的副本，笔画的点挪得准，外框却是按单精度相加挪的，会偏出一个舍入误差。按范围出图时窗口就是图面的范围，贴在范围边上的那一笔，外框偏到窗外一个单精度步长，就被丢掉。图例是散图元时没有副本，所以基线没有这个问题；任何有两个以上引用的图块（DWG、DXF 图纸上的也在内）都可能碰到。改成：外框判在窗外的图元，按它真正画的坐标再量一次，真在窗外才丢。普通图元和块的原件，外框本来就是按自己的点算的，结果和以前一样；会变的只有副本。
2. **改之前丢不丢这一笔，理论上每次运行可以不同**。哪个引用当原件，由谁先算到决定，而图元是并行算的（`src/scene/mod.rs`：一条路按 256 个一批，另两条路逐个并行）。那张图上贴着左边的图例有三个，丢的只有一个；量过的 5 次丢的都是它。这一条是读代码得出的，没有量到过两次运行不同。

**检查点一**（2026-11-20）

1. **自动化接口报的图元数把块定义里的图元也算在内**（§5）。§5 写的是「图例从一组线、圆、文字变成一个 `Block Reference`」，实际还多一层：无界面方式下 `OPEN` 和 `entities` 报的样例图元数从 10,275 变成 7,361，是模型空间的 6,390 个（592 个块引用加 5,798 个散图元）加上 119 个定义里的 971 个；`query` 把定义里的图元也逐个列出来，它们的 `space` 是块名，不是 `*Model_Space`。这是接口对图块原有的做法，本计划没有改这部分代码。依赖这些输出去数图面上有多少对象的脚本，要按 `space` 筛。
2. **量用时的基线程序换了一个**（成功标准第 11 条）。清单里写的基线程序 `baseline\OpenCADStudio.exe` 和分支不是同一个编译器编的，比用时不公平，所以用同一个编译器从 `5171d197b` 另编了一个当基线。两个基线程序给样例出的 SVG 逐字节相同，对图的结论与用哪个无关。SB-10 量用时也用同一个编译器编的基线。
3. **用时的读数随机器状态抖动，「3 次取中位数」不够稳**（成功标准第 11 条）。基线和分支交替各开 15 次样例，中位数之比四次量得 1.032、1.032、1.088、1.013，都在 1.1 以内；同一个基线程序四次的中位数从 1,854 到 2,138 ms 不等，因为别的窗口也在这台机器上编译。SB-9 的预算测试和 SB-10 的实测，基线和分支要在同一次运行里交替着量，多量几轮，并记下机器当时在跑什么；照这个抖动，只量 3 次、和一个事先写死的数比，结果可能时过时不过。

**SB-4b**（2026-11-20）
