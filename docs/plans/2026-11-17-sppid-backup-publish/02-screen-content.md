## 1. 导航

- 加一项「备份数据包」，画面 id 为 `backup`（与现有 `drawings`、`editor` 等英文单词 id 对齐）。
- **放在 `设计` 组**（S1 已定，紧挨「图纸管理」和「P&ID 编辑器」；画的时候若需微调位置以设计稿为准）。
- 这个画面的数据来自本机的备份包，不来自协同服务器。没登录、没连服务器时照样可用。画面上不该出现项目、PBS、版本、签核这些项目库的东西。
- 加这一项时三处要一起改：设计稿的导航、画面清单 `screen-catalog.json`、代码里的画面名单。有一条测试核对这三处。清单的条目由我写，草稿在 §6。

## 2. 浏览画面的状态

五个状态，每个都要暗色和亮色。

| 状态 | 什么时候 | 画面上有什么 |
|---|---|---|
| 没打开 | 刚进这个画面，还没选备份包 | 两个入口：打开 zip、打开目录。一句说明这是什么 |
| 载入中 | 选了来源，正在还原、建索引 | 来源路径；「正在还原」；已用时间。**没有百分比**。全厂包第一次约 1 秒，解过的约 0.1 秒，所以这个状态多半一闪而过；大的 zip 第一次会久一些 |
| 已打开 | 索引建好 | §3 的各区域 |
| 图读不出 | 已打开状态下，选中的那张图读不出图内对象，或者文件缺失 | 图纸那一行有标记；详情区显示数据库里的字段（有的话）和一句原因；图内对象那一块显示原因，不是一张空表 |
| 出错 | 来源不存在、既没有备份内容也没有 `.pid` 图纸（`EXP-1b`）、还原失败 | 一句错误（代码给的是一句话，没有错误码）；重新选择的入口。（注：只有散放 `.pid`、没有 `Manifest.txt` 的文件夹照旧列出这些图纸，能浏览开图、能整包出 PDF，但不能导 publish 文件。） |

## 3. 「已打开」状态的各区域和数据

### 3.1 包的概要

| 数据 | 例（全厂包） | 一定有吗 |
|---|---|---|
| 工厂名 | `SQPlant` | 清单文件里有才有 |
| 软件版本 | `7.02` | 同上 |
| 备份类型 | `2` | 同上 |
| 备份时间 | `07/19/2026 20:13:24`，原样的字符串 | 同上 |
| 来源路径 | `D:\…\pid-test-data` | 有 |
| 来源方式 | 「直接使用目录（只读）」或「已还原到 某目录」 | 有 |
| 数量 | 53 张图，15 个包内文件，645 个参考数据文件，若干条警告 | 有 |

SQL Server 包没有可读的数据库，概要里只有清单文件的字段和数量；只有散放 `.pid` 的目录没有清单字段，只有路径和图纸数量。

### 3.2 装置组树

- 节点是装置组，可以嵌套。每个节点有名字和完整路径，如 `SQPlant / 00 / 00`。
- 每个节点能给出：直接属于它的图纸数，含下级的图纸总数。
- 两个特殊的组：包里有文件但数据库没登记的图（代码里叫 `Unregistered`），没有组的图（代码里叫 `(ungrouped)`）。界面上的中文叫法由你定。
- SQL Server 包或散放 `.pid` 目录读不到数据库，树退化成按文件夹分。

### 3.3 图纸清单

每张图能给出：

| 数据 | 说明 |
|---|---|
| 名字 | 数据库里的图名；没登记的用文件名 |
| 所在组 | 完整路径 |
| 文件在不在 | 数据库登记了但包里没有文件的，标「缺文件」，不能打开 |
| 数据库里的字段 | 图纸表这一行的全部列，若干对「列名：值」，空值也在。有哪些列由备份包决定，请按「有多少显示多少」画，不要假设固定的几列 |
| 图内对象读没读出 | 选中这张图之后才去读。53 张全读约 1.3 秒，可以在后台先读好。读不出时有一句原因 |
| 能不能打开 | 只有真去打开才知道。打不开时有一句原因。全厂包 53 张里有 1 张打不开 |

- 可以按名字搜索过滤。
- 量级：全厂包 53 张，小包 7 张。清单要能滚动。

### 3.4 图纸详情：属性

- 数据库里的字段，原样列出。
- 读出图内对象之后还有：图号（`DrawingNo`）、图名、图纸对象自己的若干对属性。

### 3.5 图纸详情：图内对象

- 每个对象有：编号（UID）；类型，英文原文，如 `Instrument`；发布类别，可能没有；若干对属性，每对有接口名、属性名、值。
- 按类型分组的数量可以现算。
- 量级：全厂包 53 张图共 14 894 个对象，平均每张约 280 个。清单要能滚动，要能按类型分组或过滤，不能假设一屏放得下。

### 3.6 其他

- **警告**：若干句话，比如清单里登记了但包里没有的文件。可能是 0 条。
- **还原缓存**：占用大小、所在目录；可以清除、换位置。（注意：publish 导出或 PDF 导出进行中，清除缓存会被拒绝。）这是经典面板已有的功能，新画面要不要放由你定。
- **库表、枚举映射、参考数据文件、图纸体检**：第一版不搬进新画面（地图 §8 第 2 问），留在经典面板。新画面可以放一个去经典面板的入口，也可以不放。

### 3.7 打开图纸

- 动作：双击或按钮。结果是：若这张图尚未打开，编辑器画面多一个标签页（若最前面是启动时未改过的空白图则复用它）并切到编辑器，窄画布下自动拉远保证整张图幅完整可见（`RD-7`）；若这张图已经在某个标签页里打开，则直接切到那个标签页，不再重开第二份（`RD-6`）。
- 打开要 0.1 到 6 秒（发布版开一张实际图纸约 1.4 秒，调试版最慢约 6 秒）。要有「正在打开」的表示，没有百分比。
- 打不开：留在本画面，显示原因。
- 从编辑器回到本画面时，之前打开的包、选中的图还在。

## 4. 导出（两条独立导出线：publish 文件与 PDF）

按已定决定 P1、P2（`plan.md` §3、`SPEC-sppid-pdf.md` §9），publish 文件和 PDF 是**两个独立入口**，互不拖累，也可以同时在后台跑，且可以把两样先后导进同一个交付目录使 `<图名>_Data.xml` 与 `<图名>.pdf` 成对。

### 4.1 入口与可用条件

| 入口按钮 | 对应引擎 | 可用条件 | 不可用时的原因 |
|---|---|---|---|
| **导出 publish 文件**（不要叫「发布」，免得和平台发布包 `PIDPUBLISH` 混） | `src/io/pid_backup_export.rs`（`PIDBACKUPEXPORT`） | 有已打开的备份包，包根目录有 `Manifest.txt`，且当前没有 publish 导出在跑 | 没打开备份包；只是散放 `.pid` 的目录（没有 `Manifest.txt`）；正在导出 publish 文件 |
| **导出 PDF** | `src/io/pid_backup_pdf.rs`（`PIDBACKUPPDF`） | 有已打开的备份包（散放 `.pid` 目录也可），至少有 1 张带文件的图纸，且当前没有 PDF 导出在跑 | 没打开备份包；包里没有带文件的图纸；正在导出 PDF |

- 两样都是一次导整包，不能勾选几张图。
- **同一个交付目录成对的顺序**：如果用户要把 publish 文件和 PDF 放在同一个目录里交付，必须**先导 publish 文件**（它要求目标目录为空或不存在），**再导 PDF**（只要目录里还没有同名的 `.pdf` 或 `_PdfIndex.json`，允许目录里已有 `_Data.xml`、`_Meta.xml`、`_Index.json`）。对话框里可以写一句提示说明这一点。

### 4.2 对话框

**（A）导出 publish 文件对话框**

| 项 | 说明 |
|---|---|
| 输出目录 | 必填。必须是不存在的或空的目录，且不能落在备份包或还原目录内部；选了非空目录要当场提示（引擎会报前 5 个文件名和总数） |
| 工厂名 | 默认 `P01`，可改 |
| 参考目录 | 可选。给了就顺带和里面的 `_Data.xml` 比对（支持扁平目录或带 `01/02/03` 子目录的嵌套验证集，自动按文件名或唯一 `DocUID` 配对） |
| 提示 | 包里有几个图纸文件；SQL Server 包加一句「SQL Server 包的导出没有验收过」 |

**（B）导出 PDF 对话框**

| 项 | 说明 |
|---|---|
| 输出目录 | 必填。不能落在备份包或还原目录内部；目录可以非空（例如刚导完 publish 文件的目录），但不能已有本次要写的同名 `.pdf` 或 `_PdfIndex.json`（冲突时引擎报前 5 个文件名和总数） |
| 提示 | 共几张图纸（其中几张无文件）；SQL Server 包同样加一句「没有验收过」 |

### 4.3 进行中

| 项 | 导出 publish 文件 | 导出 PDF |
|---|---|---|
| 能给出的进度数据 | **「正在导出」+ 已用秒数**（无百分比、无「第几张」） | **「正在导出」+ 已完成张数 / 总张数**（`PdfProgress` 两个原子计数，如 `18 / 53`，可画进度文字或按张数算的进度条）+ 已用秒数 |
| 能否取消 | 不能取消 | 不能取消 |
| 全厂包（53 张）实测用时 | 约 23–30 秒 | 约 45–56 秒（正式构建约 52 秒） |
| 窗口交互 | 后台线程执行，期间可以切画面、平移缩放看图；不该用锁死整窗的遮罩，切回本画面还能看到它在跑 | 同左；两样同时跑时各自显示各自的状态 |

### 4.4 结果

**（A）publish 文件导出结果（`ExportOutcome` / `ExportError`）**

| 数据 | 例（全厂包） |
|---|---|
| 用时 | `elapsed`（如 28.2 秒） |
| 写出的图数、文件数 | `written`（53 张），`files`（160 个文件） |
| 失败计数 | `failed`（0；注意这是 `pid-parse` 的失败项计数，坏一个压缩卷记 1） |
| `.pid` 文件交代 | `pid_entries`（53 个）：对上图纸 53，`templates` 图框模板 0，`unmatched` 没对上 0 |
| 没有 `DrawingNo` 的图 | `without_drawing_no`（2 张，编号取自数据库） |
| 四个问题/提醒名单 | ① `unwritten`：没写出的图（图名 + 原因列表）；② `noted`：写出但带说明的图；③ `other_problems`：整包层面其余问题；④ `warnings`：提醒。均可能为 0 条，也可能几十条（清单文件 `_Index.json` 有全量） |
| 比对结论（给了参考目录才有，`GateSummary`） | 四个数：`clean`（一致）、`dirty`（有差异）、`revision_mismatch`（参考是另一版）、`unpaired`（没有参考），例如原验收目录 `7 / 0 / 4 / 42`、新 94 套目录 `15 / 32 / 0 / 6`；另有 `lines` 逐张比对明细 |
| SQL Server 提示 | `sql_server() == true` 时提示「SQL Server 包的导出没有验收过」 |
| 输出目录与清单 | 输出目录路径、`_Index.json` 路径（可放「打开目录」「打开清单」动作） |

整次失败时返回 `ExportError`：错误码（8 种：`SPPID_EXPORT_NO_PACKAGE`、`SPPID_EXPORT_NOT_A_BACKUP`、`SPPID_EXPORT_TARGET_NOT_EMPTY`、`SPPID_EXPORT_TARGET_INVALID`、`SPPID_EXPORT_REFERENCE_INVALID`、`SPPID_EXPORT_BUSY`、`SPPID_EXPORT_UNSUPPORTED`、`SPPID_EXPORT_FAILED`）加一句原因。

**（B）PDF 导出结果（`PdfOutcome` / `PdfError`）**

| 数据 | 例（全厂包） |
|---|---|
| 用时 | `elapsed`（如 54.7 秒） |
| 张数交代 | 共 `pages.len()` 张：`written` 写出（53 份），`failed` 有文件但未写出（0 张，重名的第二张也计入此处并说明原因），`without_file` 库里登记但无文件（0 张） |
| 缺符号统计 | 从 `pages` 汇总：多少张图有找不到的符号文件（全厂包 15 张共 22 处），每张缺哪些符号在 `PdfPage.missing_symbols` |
| 没写出 PDF 的图 | 名单：图名 + `error` 原因（重名跳过、损坏文件、缺字体等） |
| 每张图的明细（`PdfPage`） | 文件名、字节数、图元数、纸幅 `page_mm`、所用图框模板名 `template`、符号找到数/引用数、账目 `ledger` |
| SQL Server 提示 | SQL Server 包同样提示「没有验收过」 |
| 输出目录与清单 | 输出目录路径、`_PdfIndex.json` 路径（可放「打开目录」「打开清单」动作） |

整次失败时返回 `PdfError`：错误码（6 种：`SPPID_PDF_NO_PACKAGE`、`SPPID_PDF_NOTHING_TO_PLOT`、`SPPID_PDF_TARGET_INVALID`、`SPPID_PDF_TARGET_HAS_FILES`、`SPPID_PDF_BUSY`、`SPPID_PDF_FAILED`）加一句原因。

两种导出的结果都按这三种形态画：
1. 全部写出，没有问题/缺符号提醒。
2. 部分未写出，或有提醒/缺符号/参考目录比对结论：数字加可滚动名单。
3. 整次失败：错误码加一句话。

## 5. 给不出的东西，请不要画

- **publish 导出**的进度百分比、当前第几张、预计剩余时间（`pid-parse` 整包入口一次做完，只有已用秒数；**PDF 导出有「已完成几张 / 共几张」**，但也无预计剩余时间）。
- 两种导出和载入的**取消按钮**。
- 导出时勾选部分图纸。
- 图纸的缩略图。开一张图要 0.1 到 6 秒，没法给清单里每张都画。
- 图纸的版本、状态、签核、负责人。那是项目库的东西。
- 导出历史。程序不记历次导出，只知道这次运行里 publish 和 PDF 各自的上一次。
- 备份包清单文件里的账号、口令。程序一律不显示。

## 8. 画框细节约定（2026-11-20 已按建议确认）

以下五项已按 `SPEC-sppid-screen.md`（S1–S4）与 `SPEC-sppid-export-ui.md`（U1–U3）推荐方案定下（在 Pencil 中画框时若你另有微调，实现时照设计稿）：

1. **导航位置（S1）**：放在 **`设计`** 组，紧挨「图纸管理」和「P&ID 编辑器」，名称 **「备份数据包」**（`Nav backup`）。
2. **两个特殊组的中文名（S2）**：`Unregistered` 画作 **「未登记图纸」**，`(ungrouped)` 画作 **「未分组」**。
3. **还原缓存与经典面板入口（S3）**：在包概要右上角放次要入口（如 **「清理还原缓存」** 与 **「在经典面板中查看库表」** 两个小按钮或次要菜单）。
4. **导出进行中的提示位置（U1）**：**两处联动**——`backup` 画面内放完整的进行中条，外壳底部状态栏右侧顺带放一句简短全局提示（如 `正在导出 PDF 18/53`）。
5. **publish 和 PDF 两个导出结果的摆放（U3）**：在包概要下方放各自最近一次状态摘要条（未导出时不占空间；完成后显示摘要 + **「查看详情」「打开目录」「打开清单」** 动作，展开显示名单与比对明细）。
