# Open CAD Studio 使用教程

本文面向第一次使用 Open CAD Studio 的用户，介绍从启动、打开图纸、绘制对象到保存文件的常用操作。界面会随着版本持续变化，以下截图基于当前开发版。

## 启动应用

如果你使用发布版，在 Windows 上直接运行 `OpenCADStudio.exe`。如果从源码启动，在项目根目录执行：

```powershell
cargo run
```

启动后会进入欢迎页。左侧是最近打开的文件列表，中间区域提供新建、打开、插件、发布说明和反馈入口。顶部是 Ribbon 功能区，常用命令按 `Draw`、`Model`、`Insert`、`Annotate`、`View`、`Manage` 等页签分组。

![Open CAD Studio 启动页](screenshots/open-cad-studio-start.png)

## 新建或打开图纸

在启动页点击 `New Drawing` 可以创建空白图纸。点击 `Open File...` 可以打开已有 DWG 或 DXF 文件。打开后的文件会以标签页形式显示，左侧 `Properties` 面板用于查看或编辑当前选中对象的属性。

也可以使用顶部菜单或快捷命令打开文件。常用文件能力包括 DWG/DXF 读写、STL/STEP/OBJ 相关导入导出、PDF 输出、外部参照和块写出。

## 认识主界面

主界面主要分为五个区域：

- 顶部 Ribbon：按任务分组放置绘图、修改、标注、图层、块和属性工具。
- 中央绘图区：显示模型空间或布局空间内容，鼠标用于选择、绘制、平移和缩放。
- 左侧属性面板：选中对象后显示对象属性；未选中对象时显示 `No Selection`。
- 文件标签：在 `Start` 和各个图纸之间切换，也可以通过 `+` 创建新图纸。
- 视图与样式控件：绘图区上方可切换 `Wireframe 2D` 等显示样式。

## 绘制基础图形

进入 `Draw` 页签后，可以直接点击图标创建常用对象：

- `Line`：绘制直线。
- `Polyline`：绘制连续折线。
- `Circle`：绘制圆。
- `Arc`：绘制圆弧。
- `Text`：插入文字。
- `Dimensions`：创建尺寸标注。
- `Leader`：创建引线标注。

基本流程通常是：选择工具，按命令提示指定第一个点，继续指定后续点或参数，最后按 `Enter`、`Esc` 或根据命令提示结束。

## 编辑对象

绘制完成后，可以使用 `Modify` 区域的工具编辑对象。常用命令包括：

- `Move`：移动对象。
- `Copy`：复制对象。
- `Rotate`：旋转对象。
- `Scale`：缩放对象。
- `Mirror`：镜像对象。
- `Trim`：修剪对象。
- `Extend`：延伸对象。
- `Offset`：偏移对象。
- `Fillet`：创建圆角。
- `Explode`：分解块、尺寸、复合线等复合对象。

先选择对象再执行命令，或先执行命令再按提示选择对象，具体取决于命令交互。使用 `Esc` 可以取消当前命令。

## 使用捕捉与精确绘图

Open CAD Studio 支持端点、中点、圆心、象限点、交点、垂足、切点、最近点、插入点等对象捕捉。启用对象捕捉后，鼠标靠近可捕捉位置时会自动吸附到精确点位。

常用精确绘图能力包括：

- `OSNAP`：对象捕捉。
- `OTRACK` / `F11`：对象捕捉追踪。
- `DYNMODE` / `F12`：动态输入。
- 极轴追踪：按角度增量辅助绘图。
- 命令历史：使用上下方向键切换历史命令。

## 管理图层和属性

Ribbon 中的 `Layers` 区域用于管理图层。你可以创建、锁定、冻结、关闭或切换当前图层。右侧属性下拉框可以快速设置对象颜色、线型和线宽，例如 `ByLayer` 表示对象继承所属图层的属性。

典型工作流是先设置当前图层，再绘制对象。这样后续可以按图层批量控制显示、打印和属性。

## 打开 Smart P&ID（.pid）图纸

Open CAD Studio 可以直接打开 SmartPlant / Smart P&ID 的 `.pid` 文件：`Open File...` 的文件类型里选 `Smart P&ID Files`（`CAD Files` 也包含 `.pid`），或者在资源管理器里右键 `.pid` →「打开方式」选 Open CAD Studio。打开就是一次导入：文件里的线、文字、填充和审查标记被读成普通 CAD 实体，符号放置读成块引用（一个放置一个，见下文「符号是块」一段），可以像其他图纸一样选择、量测、标注和另存。

**`.pid` 是只读来源。** 程序永远不会往 `.pid` 里写字节：按 `Ctrl+S` 会直接弹出「另存为」，默认文件名是同名的 `.dwg`；命令行或脚本里把保存目标写成 `.pid` 会被拒绝并提示 `read-only Smart P&ID source`。要保留修改，另存为 DWG 或 DXF 即可，图纸里的 P&ID 语义（见下文特性面板一段）会一起保存。

**导入汇总。** 打开完成后命令行给出两行信息：第一行是画出了多少实体、来自多少条已解码记录、有多少条源记录没有画出，以及带原图图层的实体数（这两个实体数按画出来的算：一个符号放置画的笔画、填充和符号名各算一个，它的块引用不另算，所以和图上能选中的对象数不是一回事）；第二行是 `P&ID sheet layers: N, of which M start switched off`——按名字数的原图图层有几个、其中几个按文件里的隐藏状态初始关闭。图里有参数化符号时还有第三行 `P&ID driving dimensions: D on T template bodies; P placed parametric bodies carry library defaults`——文件缓存的符号库模板本体上有名字的驱动尺寸共几条、分布在几个模板本体上、有几个放置能在特性面板里看到这些库默认值（每个这样的放置在面板上对应一行「驱动尺寸（库默认）」）；没有参数化符号的图不出这一行。若样式表读取失败，还会多一行错误提示，此时线宽和颜色会退回图层默认。图纸没有声明坐标单位时也多一行（`P&ID import: the drawing states no coordinate unit; the metre was assumed.`）——坐标按米换算，英制图会整体差 25.4 倍，所以说出来；声明了单位的图不出这一行。这份摘要随文档一起交到打开完成的一步，读一次就取走，不会写进另存的 DWG / DXF；`--export` 这类没有命令行的路把它转进日志。逐条明细在日志里。

**符号从哪来。** 每个符号放置画的是这张 `.pid` 自己缓存的那份本体——SmartPlant 实际放置的那个符号版本，参数化符号则是被拉伸后的实例；符号内部处于关闭图层上的笔画（伴热线、夹套线、`NULL` 占位文字、参数化本体的构造线等，文件里标为不显示、SmartPlant 屏幕上也看不见）不画，也不进任何图层。符号内部哪几笔画成虚线，按符号自己存储里的样式表（如去外单元接续符号的虚线圆和四条虚线腿、呼吸阀的虚线唇），颜色与线宽仍按放置点名的样式。符号库只在文件没有可画的缓存本体时补位：`.pid` 通过工程参考数据共享路径引用符号库，程序会从图纸所在目录向上查找 SmartPlant 工程的 `Ref\Symbols`；找不到时，把环境变量 `PID_SYMBOL_LIBRARY` 指向本地的符号库副本。两边都没有本体的放置只显示一个位置点。日志里另有一行说明本次导入有多少放置画的是缓存本体、多少画的是库本体、跳过了多少条关闭层上的笔画；命中的符号库目录（`PID_SYMBOL_LIBRARY` 或找到的 `Ref\Symbols`）和读到的坐标单位也记在导入摘要里，同一张 `.pid` 换个目录画得不一样时由此可查。

**符号是块。** 每个画出了东西的符号放置在图上是一个块引用（DXF 里的 `INSERT`），它画的笔画、填充和符号名都在块定义里：在任一笔上点击，选中的是整个符号；选中后只有插入点一个夹点；对象捕捉照常能捕到符号里笔画的端点和圆心；移动、复制、旋转、镜像、删除和撤销都按整个符号进行，复制、镜像出来的是又一个块引用，记录与原件相同。块名是 `SPPID_` 加符号名（没有符号名的放置是 `SPPID_SYMBOL`）；同一个符号、画出来一样的放置共用一个块定义，同一个符号在图上有几种画法（比如转了方向）时，第一种用这个名字，其余依次加 `_2`、`_3`。块名里不能用的字符会换成 `_`，过长的名字会截短，撞上已有的块名时序号往后顺延，所以认符号不看块名，看特性面板的 `符号` 一行。导入出来的块引用不带旋转和缩放（转角 0、比例 1）：符号摆成什么方向、多大，已经画在块定义里。块引用在这个放置的图纸图层上；块里的笔画和填充在 `0` 层，跟着引用所在的图层显示，颜色为 `ByLayer` 的笔画取这个图层的颜色；符号名在块里的 `PID-SYMBOL-LABEL` 层上，打开这一层它才显示，移动符号时跟着走。只画出符号名的放置，块引用自己就在 `PID-SYMBOL-LABEL` 层上，打开这一层才看得见、选得到（它的图纸图层名仍写在 `sheet_layer=` 里）。文件没给出图层名的放置（语料图里没有），块引用落在程序自己的 `PID-SYMBOL` 层，填充留在 `PID-FILL` 层；其中原图隐藏的，块引用在 `PID-HIDDEN` 层，块里的实体都在 `0` 层。`PID_SEMANTICS` 记录写在块引用上——`role=symbol`、`symbol=`（符号名）、`sheet_layer=` / `sheet_layer_oid=`、`style=`、`extent=` / `driving=` / `instance=`，查到已发布数据时还有 `class=` / `label=` / `oid=` / `resolved=`；块定义里的实体只写 `role=`（`symbol` / `fill` / `symbol-label`），因为一个定义可能被几个放置共用。对一个符号用 `Explode`（分解），它变回散的实体：笔画落到引用原来所在的图层，符号名仍在 `PID-SYMBOL-LABEL`，每个实体只剩 `role=`，引用上的记录随引用一起没有了。图例识别（`PIDLEGEND`）不碰这些块引用：既不列进识别到的符号，也不进例外里的 `未知块`，`PIDLEGEND ON` / `OFF` / `PURGE` 也都不改它们的 `PID_SEMANTICS` 记录。图框（`PID-FRAME` 层）里的内容不是块，仍是散的实体。

**文字。** 文字的字高、字体和颜色按这条文字自己的格式取——SmartPlant 里选中文字设的字号和字体（管道号、位号常见的是 7 磅 Arial Narrow），而不是它段落样式上的默认值（多为 1/8 英寸 Arial）；对齐与行距仍按段落样式。一条文字里几段格式不同时（管道号的号段与分隔符、`m^3` 里的上标 `3`），整条按覆盖字符最多的那段画，日志里记一行有几条这样压平。样式表给不出可用字高的文字（语料里是一种 0.254 mm 的占位样式）仍按 2.5 mm 画，日志里同样点名。另存 DWG / DXF 时，这些文字样式写上字体文件名（如 Arial Narrow 写 `ARIALN.TTF`），重新打开或在别的 CAD 里看仍是同一种字体；本机没装的字体只能写 `txt`，导入日志里会点名。2026-09-24 之前另存的图里文字样式都是 `txt`，重新打开是笔画字体。

**线宽。** 笔画的线宽取自样式表，归到三档：0.17、0.34、0.68 mm（SmartPlant 出图的 0.48、0.96、1.92 磅三支笔），写在实体自己身上。DWG 存的不是数值，是一张固定表里的第几档——0.00、0.05、0.09、0.13、0.15、0.18、0.20、0.25、0.30、0.35、0.40、0.50、0.53、0.60、0.70、0.80、0.90、1.00、1.06、1.20、1.40、1.58、2.00、2.11 mm——这三档都不在表里。DXF 写的是数值本身，可是读它的程序可以只认这张表：DXF 库 ezdxf 的检查就把表外的线宽报成不合法，再改成表里的值。所以另存 DWG 和另存 DXF，写进文件的都是表里最接近的一档：0.17 → 0.18、0.34 → 0.35、0.68 → 0.70 mm。图里其他不在表里的线宽（0 到 2.11 mm 之间）、图层的线宽和当前线宽同样处理，离两档一样近时取宽的一档；`ByLayer`、`ByBlock`、默认和表里已有的线宽不变；超过 2.11 mm 的线宽这一步不管：在存出的 DWG 里照旧是「默认」，在存出的 DXF 里，实体和图层上的照旧是数值本身。当前线宽另有一处：取到 1.06 mm 一档的（原值 1.03 到 1.12 mm），在存出的 DXF 里是 `ByLayer`。换的只是写进文件的那一份：打开着的图仍是 0.17、0.34、0.68 mm；重新打开存出的 DWG 或 DXF，看到的是 0.18、0.35、0.70 mm。原来的三个数只在 `.pid` 里：另存成 DWG 或 DXF 都留不住，要原值就从 `.pid` 重新打开。不只是「另存为」，程序别处写 DWG、DXF 时也是这样：`--export` 转换、`WBLOCK`、`ARCHIVE` / `ETRANSMIT` 打包、图纸集改写图纸文件、参照编辑存回参照文件、浏览器版的保存和自动保存；一张带着表外线宽的 DXF，用这个程序打开再存，线宽也换成表里的。标注样式、多重引线和表格边框里的线宽不在这一步里。Python 插件的 `ocs.export_layer_dwg` 不走这一步，表外的线宽在它存出的 DWG 里仍是「默认」。2026-11-22 之前另存的 DWG 里这些线宽存成了「默认」，重新打开后粗线细线不再有区别；要找回来，从 `.pid` 重新另存一次。同一天之前另存的 DXF 里是原来的三个数，用这个程序打开仍是 0.17、0.34、0.68 mm，再存一次才换。

**图层。** 导入后每个实体的图层就是 SmartPlant 里它所在的图纸图层名——`Default` / `Labels` / `ConsistencyChecks` / `HiddenObjects` 等，不加前缀，同名图层跨存储合并为一层；符号放置落在图纸图层上的是它的块引用，块里的笔画和填充在 `0` 层，跟着引用所在的图层显示（见上文「符号是块」一段）；图层表列出的是原图自己的全部图层（包括没有画出实体的），每层的开关按文件里的显示状态设定，原图隐藏的层直接为关，在图层管理器里可以像普通图层一样开关。程序自己造出的实体（图框、符号名、连通链诊断线）不在任何图纸图层上，文件没给出图层名的实体也没有图纸图层可去，它们都留在程序自己的 `PID-*` 层上。这些层里 `PID-FRAME` 每张图都有，其余的只在有实体落上去时才出现：

| 图层 | 内容 | 初始 |
|---|---|---|
| `PID-FRAME` | 图框：按文件页面尺寸画出的矩形；找得到图纸链接的图框模板（`.igr`）时，模板里的图框、标题栏等内容（线条、文字、填充）也在这一层。文件里读不到页面尺寸、也没找到模板时不画图框，这一层是空的 | 开 |
| `PID-SYMBOL-LABEL` | 符号名标签；只画出符号名的符号放置，它的块引用也在这一层 | 关 |
| `PID-CONNECTIVITY` | 连通链诊断线 | 关 |
| `PID-GEOMETRY` | 文件没给出图层名的线条 | 开 |
| `PID-TEXT` | 文件没给出图层名的文字 | 开 |
| `PID-FILL` | 文件没给出图层名的填充（落在 `PID-SYMBOL` 层的符号放置，块里的填充也在这一层） | 开 |
| `PID-SYMBOL` | 文件没给出图层名的符号放置（它的块引用） | 开 |
| `PID-POINT` | 文件没给出图层名的审查标记：标记的点，以及文件没点名状态的记号 | 开，不打印 |
| `PID-POINT-WARNING` / `PID-POINT-ERROR` / `PID-POINT-APPROVED` | 文件没给出图层名的审查标记里，状态是警告 / 错误 / 已批准的记号 | 开，不打印 |
| `PID-HIDDEN` | 原图隐藏、但文件没给出图层名的内容，不论线条、文字还是符号放置（不隐藏的归上面几层） | 关 |

表里前三层是平常见得到的：语料四图和另外量过的 154 张图上，程序自己的层只出现过这三个，其中 `PID-CONNECTIVITY` 只在一张图上有；后面几层只收文件没给出图层名的实体，在这些图上一次也没有出现。「不打印」指图层的打印开关初始为关；原图的 `ConsistencyChecks` 图层（审查标记大多在这一层）也是这样，开着，打印开关为关。另有 `PID-ANNOTATION` 层（初始为关）和角色 `annotation`，是留着的名字：眼下的导入不产生这类实体，图里不会有。

分类信息没有丢：每个实体的 `PID_SEMANTICS` 扩展数据里写着 `role=`（角色，共十二个词：`geometry` / `text` / `symbol` / `symbol-label` / `point-ok` / `point-warning` / `point-error` / `point-approved` / `annotation` / `connectivity` / `fill` / `frame`，其中 `annotation` 眼下不会出现）与 `style=`（原图样式名，如 `Primary Piping - New`），特性面板的「角色」行和图层管理器「图纸图层」视图下方的「角色」一段读的就是它。审查标记占四个 `point-*`：标记的点本身一律是 `point-ok`，不论状态；画出来的记号笔画按状态是 `point-warning` / `point-error` / `point-approved`，文件没点名状态的记号也是 `point-ok`。图框模板里的内容，线条、文字、填充都一样，角色是 `frame`。符号放置的这份记录写在它的块引用上（`role=symbol`、`style=`，另有 `symbol=` 等，见上文「符号是块」一段），块定义里的实体只写 `role=`。**另存为 DWG / DXF 后，第三方查看器里看到的图层名 = SmartPlant 原图图层名；要按导入器的分类取实体，读 XDATA `PID_SEMANTICS` 的 `role=` / `style=`——符号放置读它的块引用（`INSERT`）上的那一份：分类是 `role=symbol`，样式是 `style=`，符号名是 `symbol=`，图纸图层是 `sheet_layer=`；块定义里的实体只有 `role=`，它们所在的 `0` 层或 `PID-*` 层不是图纸图层。** 2026-09-21 之前另有一种「分类合成层」读法（`PID-GEOMETRY` / `PID-TEXT` / `PID-SYMBOL` / `PID-POINT-*` / `PID-STYLE-<样式名>` / `PID-HIDDEN` 各占一层，隐藏内容挪去 `PID-HIDDEN`）和在两种读法之间切换的环境变量，且以它为默认；两种读法画出来的图一模一样（颜色、线宽都在实体自己身上），只差图层表，已一并退役——设了那个变量也没有反应。退役的是这种读法，不是这些层名：`PID-STYLE-<样式名>` 不再出现，其余的如今只收文件没给出图层名的实体（见上表）。

**图纸图层视图。** 打开 `.pid` 后，图层管理器的工具栏多出 `图层` / `图纸图层`（英文界面为 `Layers` / `Sheet layers`）两个切换按钮。切到 `图纸图层`，表格按原图图层（`Default` / `Labels` / `ConsistencyChecks` / `HiddenObjects` 等，不含程序自己的 `PID-*` 层）列出每层的实体数，下方 `角色`（Roles）一段列出这张图里有实体的角色及实体数，没有实体的角色不列，次序同「图层」一段里 `role=` 的那十二个词（`geometry` / `text` / `symbol` / `symbol-label` / `point-*` / `annotation` / `connectivity` / `fill` / `frame`）。数的是 `PID_SEMANTICS` 里写着这个图层名（`sheet_layer=`）或这个角色（`role=`）的实体：一个符号放置在图纸图层那几行里算 1 个（它的块引用）；在角色那几行里，块引用算 1 个 `symbol`，块定义里的实体按各自的角色（`symbol` / `fill` / `symbol-label`）各算 1 个，几个放置共用的块定义只算一次——所以角色行的数字不是图上画出的笔画数。点击行尾的眼睛可以单独关掉或打开某个原图图层或某个角色：一个实体只要所属图层或角色任一被关就不显示。关掉一个图纸图层，这一层的符号放置整个不显示；关掉角色 `symbol`，所有符号放置整个不显示（连同里面的填充和符号名）；关掉 `fill` 或 `symbol-label`，符号里只是填充或符号名不显示，其余笔画还在。这些开关记录在图纸里（`PID_VIEW_FILTER`），另存为 DWG/DXF 后再打开仍然有效，也可以撤销。原图隐藏的图层初始为关；把它打开时，程序会连带打开图层表里同名的那个图层，实体才看得见（2026-09-21 之前另存的图里，隐藏图层的实体放在 `PID-HIDDEN` 上，连带打开的是它）；关掉不动图层表。文件没给出图层名的隐藏内容在图纸图层那几行里没有开关：它不写 `sheet_layer=`，哪一行都不是它的，要看它，切回 `图层` 视图把 `PID-HIDDEN` 打开。搜索框对两种视图都有效。

**特性面板。** 选中导入的实体，左侧特性面板会多出 `P&ID` 一组只读属性：`类型`（已发布数据里的对象类，如 `PIDPipeline`）、`角色`（导入时读到的角色，即「图层」一段里 `role=` 的那套词）、`符号`（仅符号放置有：它放的是哪个符号，名字与图纸里写的一字不差，即 `symbol=`）、`驱动尺寸（库默认）` 与 `本体尺寸`（仅符号放置有，见下一段）、`位号` 或 `管线号`、`匹配方式`（若来自图例识别）、`图纸图层` 与 `图层 OID`（原图图层名及其在文件里的编号）。这些信息写在实体的 `PID_SEMANTICS` 扩展数据里（符号放置的写在它的块引用上），导出 DXF/DWG 时保留。选中的是符号放置时，面板里还有块引用自己的几行：插入点、比例、旋转和块名。

**符号的三个尺寸。** 点选一个符号放置的任一笔画或它旁边的符号名（符号名要先打开 `PID-SYMBOL-LABEL` 图层才看得见），选中的是这个放置的块引用，`P&ID` 组会多出 `本体尺寸`——这张图上该符号本体的外框宽 × 高（毫米，两位小数，按放置的旋转 / 缩放量得，量的就是屏幕上画出的那些笔画——`.pid` 自己缓存的实例本体里文件显示着的那部分）；如果它是参数化符号且文件里配得上它的库模板，还会多出两行：`驱动尺寸（库默认）`——模板本体上按名字列出的驱动尺寸，如 `Top 20.32 mm · Left 114.30 mm · Right 114.30 mm`；`驱动尺寸（本图实例）`——这张图上该实例实际被放置成的参数，如同一个 Manifold 的 `Left 57.91 mm · Right 114.30 mm · Top 35.59 mm`（读自符号定义缓存里实例自己的 flavour 记录；没被拉伸过的实例这一行等于库默认）。**中间那行是符号库的默认值，不是这张图上的实际尺寸**：SmartPlant 放置后被拉伸过的实例，文件里那份变量副本仍等于库默认，实际参数另存一处，所以三行并排给出，分别是「库里怎么定义的」「这张图上放成了多大」「画出来的外框多大」。非参数化符号（阀门、仪表等）只有 `本体尺寸` 一行。三个值分别以 `extent=` / `driving=` / `instance=` 写在这个放置的块引用的 `PID_SEMANTICS` 里（块里的实体不带），随 DWG/DXF 保留。

## 浏览 SmartPlant P&ID 备份

一个 SmartPlant P&ID 备份是一份 `.zip`，或者一个摊开的备份目录，里面装着 `Manifest.txt`、`Export.dmp`、若干 `PlantData~*` 归档和 `Ref` 参考数据。要整体查看这个备份里有什么，运行 `PIDBACKUPOPEN`，或从应用菜单选 **Open P&ID Backup...**（中文界面为「打开 P&ID 备份…」）。程序会显示右侧的 `P&ID Backup` 停靠面板，并让你选备份来源——`Zip` 是压缩包，`Folder` 是已经摊开的目录。

面板上半是浏览树，四个顶层分组：

| 分组 | 内容 |
|---|---|
| 备份文件 | `Manifest.txt` 摘要，以及备份根目录下的每个文件（`Manifest` / `Export.dmp` / `RefData~*` / `PlantData~*`），带格式、大小和归档成员数 |
| 装置组与图纸 | `T_DRAWING` 里的装置组树，每个组下是它的图纸；表里没登记的 `.pid` 归到 `Unregistered`，既没有目录也没有装置组的归到 `(ungrouped)` |
| 图纸内容 | 展开一张图纸时按需读取它的模型项：类型分组、每一项的 UID、对象类和已发布属性 |
| 参考数据 | `Ref` 目录树与其中每个文件 |

下半是详情区：点树上的任一节点，这里列出它的字段。选中图纸行时给出 `T_DRAWING` 的字段、还原出来的 `.pid` 文件路径和一个 **打开图纸** 按钮。

**双击图纸**在新标签页里打开它——和 `OPEN <路径>` 是同一条路，`.pid` 仍然是只读来源（见上一节）。

**符号文件（`.sym`）。** 在树上选中一个 `.sym`——`参考数据` 里的文件、备份里压缩包（`RefData~*.zip`）的成员，或者单独登记成一个备份文件的都算——详情区在文件名和大小下面给出它的缩略图和图元统计；读不出来或者没有可画的图元时，写明原因。**双击这个 `.sym`**，或者按详情里的 **打开符号** 按钮，在新标签页里把它按自己的坐标画出来：符号的原点在图纸原点，不旋转、不缩放，单位毫米，标签名是符号名；同一个 `.sym` 已经开着时切到它的标签，不再开一个。`.sym` 是只读来源，程序不写回它；在符号的标签页里画了东西，只能另存成图纸。SDI 模式下不打开，因为符号要单独占一个标签页。缩略图和标签页画的都是 `.sym` 里自己存的那一份图元：虚线画成实线，颜色是 `.sym` 自己写的，和这个符号摆到图纸上以后的样子可能不一样。

**搜索框。** 面板上的搜索框按名字找图纸和参考文件。框里有字时，树上只留下名字里含这些字的图纸（连同它上面的装置组）和 `参考数据` 里名字含这些字的文件（连同它上面的各级目录），留下的都展开着；不分大小写，首尾的空格不算。比的是文件自己的名字，不比目录名；`备份文件` 分组在搜索时不显示，压缩包里的成员搜不到。留下来的行和平时是同一个节点：单击看详情和缩略图，双击打开。清空搜索框，树回到搜索之前的样子。命令行里 `PIDBACKUPOPEN Search <词>` 做的是同一件事，并报出留下几张图纸、几个参考文件；不带词是清空。

备份怎么读：选中的是压缩包时，程序把它解到一个工作目录再读；选中的是已经摊开的目录时，就地读取，一个字节都不写。`Export.dmp` 是 Oracle `exp` 导出时，面板能读出装置组和图纸表；如果它缺失、是 SQL Server 的 MTF 流，或者读不动，图纸仍按文件夹列出来，并在树的 `备份文件` 分组里说明原因。`Manifest.txt` 登记了但备份里没带的 `RefData` 条目会标成缺失并给出一条警告，不会静默吞掉。

面板状态挂在应用上，切标签页不会丢；同一个备份再执行一次 `PIDBACKUPOPEN` 直接显示已索引的内容，不会重新解包。

## 校正 P&ID 图例

打开 P&ID 图纸后，在 `Draw` 页签的 `P&ID` 区域点击 `P&ID 图例`，或运行 `PIDLEGEND LIST`。图例面板会列出当前识别到的符号和位号；点击一行可以选中并定位该符号。

面板底部的 `例外` 区域默认折叠，数字与 `PIDLEGEND REPORT` 的例外汇总使用同一口径。展开后按 `未知块`、`未命名形状`、`无主位号`、`范围标注`、`重复位号` 分组；点击任一明细会选中原始块、笔画或文字并缩放到其位置，方便直接修图或补规则。

自动识别不准确时，可以把正确的几何和位号文字组成一个明确的 P&ID 符号：

1. 选中符号的几何和它自己的位号文字。
2. 点击 `P&ID 组合`，或在视口右键菜单中选择 `组合为 P&ID 符号`。命令行也可以运行 `PIDGROUP GROUP`；普通 `GROUP` 会额外询问组名。
3. 组合会按自动识别的同一套文字规则读取位号，并把 `tagName=…;tagSource=auto` 写入原生 DXF/DWG GROUP 的描述。图例中的手动组带 `手` 角标。
4. 要调整成员时，选中组内任一对象，点击 `取消 P&ID 符号组合`，或运行 `PIDGROUP OFF` / `UNGROUP`；重新选择正确成员后再次组合。右键菜单只在当前选择属于某个组时显示取消组合入口。

选中手动组的任一成员后，左侧特性面板的 `P&ID` 区域可以直接修改 `位号 (tagName)`。输入与组内文字不同的值时来源变为 `手动`；清空，或改回文字本来能读出的值，来源恢复为 `自动`。自动来源会在下一次识别时重新读取当前文字。

默认的 `PICKSTYLE` 会让点击一个成员时选中整组。需要单独编辑组内文字时，可以按住 `Ctrl` 选择，或临时运行 `PICKSTYLE 0`；完成后再恢复原设置。保存为 DXF 或 DWG 后，组、描述和位号会一起保留。导出 SVG 时，已识别的符号写成 `<g tagName="…">`，组内几何与位号文字都属于该节点。

通过 `OpenCADStudio --serve` 启动的逐行 JSON 自动化接口使用同一套语义。先用 `query` 取得十六进制句柄并通过 `select` 建立当前选择，再调用 `pid_group`：

```json
{"op":"select","handles":["1A","1B"]}
{"op":"pid_group","what":"create"}
{"op":"pid_group","what":"tag","tag":"XV-0001"}
{"op":"pid_group","what":"auto"}
{"op":"pid_group","what":"off"}
```

`create`、`tag`、`auto` 和 `off` 分别对应 `PIDGROUP GROUP`、`PIDGROUP TAG`、`PIDGROUP AUTO` 和 `PIDGROUP OFF`。响应中的 `groups_before` / `groups_after` 会返回组句柄、组名、位号来源和成员句柄，`changed` 表示本次是否改变了组状态。

要把识别结果交给其他程序，可以直接运行：

```text
PIDLEGEND EXPORT D:\output\sheet.json
PIDLEGEND EXPORT D:\output\sheet.csv
```

扩展名决定格式。JSON 与 `dxf_legend --json` 使用同一个序列化器，包含符号、位号、例外和完整管线 run；CSV 先给出 `class,label,tag,x_mm,y_mm,lines,source` 符号表，再给出 `line,family,runs,length_mm,from,to` 管线表。导出会按需重新识别，但不会绘制覆盖层或写入实体 XDATA，所以在第一次 `PIDLEGEND ON` 之前、或 `PIDLEGEND OFF` 之后都可以使用。

逐行 JSON 自动化接口提供同一份结构化结果：

```json
{"op":"pid_legend","what":"recognise"}
{"op":"pid_legend","what":"report"}
{"op":"pid_legend","what":"export","path":"D:\\output\\sheet.json"}
{"op":"pid_legend","what":"export","path":"D:\\output\\sheet.csv"}
```

三种动作都返回相同的识别字段；`report` 额外返回命令行报告数组，`export` 额外返回写入路径、格式和字节数。

## 标注、文字和表格

`Annotate` 页签集中放置文字和标注能力。常用功能包括：

- `TEXT` / `MTEXT`：创建单行或多行文字。
- `DIMLINEAR`、`DIMALIGNED`、`DIMANGULAR`、`DIMRADIUS`、`DIMDIAMETER`：创建不同类型尺寸。
- `DIMSTYLE`：管理尺寸样式。
- `MLEADER` / `MLEADERSTYLE`：创建和管理多重引线。
- `TABLE` / `TABLESTYLE`：创建表格和表格样式。

创建标注前建议确认当前图层、文字样式和尺寸样式，避免后续逐个修改。

## 使用插件

启动页和 Ribbon 中提供 `Plugins` / 插件管理入口。当前版本支持外部插件包发现、启用/禁用、安装、卸载和升级。插件通常放在项目或应用识别的插件目录中，并通过插件管理器加载。

如果插件没有出现，先确认插件包结构和清单文件是否正确，再重新打开插件管理器刷新状态。

## 常见问题

如果应用无法启动，先在项目根目录运行：

```powershell
cargo check
```

如果 `cargo check` 通过但 `cargo run` 失败，优先查看终端中的错误信息。当前开发版编译时可能会出现 warnings；warnings 不一定阻止运行，但应在发布前清理。

如果打开文件后显示异常，先确认文件格式和版本。项目支持 DWG/DXF R13 到 R2018；包含外部参照、特殊字体、复杂线型或大型 3D 实体的文件，首次打开和渲染可能需要更长时间。

如果操作过程中界面看起来没有响应，先按 `Esc` 取消当前命令，再尝试切换工具或重新选择对象。
